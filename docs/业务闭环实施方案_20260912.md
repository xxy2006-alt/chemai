# ChemAI 智能体业务闭环全量实施方案

> 2026-09-12 · 来源：架构评审（5 候选）+ grill-with-docs 逐项定案
> 总纲：ADR-0012「业务逻辑住在 service module，agent 工具与 chem_skills 一律为 adapter」

## 一、目标闭环

```
教师 Agent ──诊断──▶ 练习分发 module ──▶ StudentNotification(inbox+网关)
                                         │
                                         ▼
                                      学生作答（m/practice，选择题+主观题）
                                         │
                                         ▼
              学情 ◀── 诊断 ◀── StudentAnswer ◀── 判卷中心(grade/save/override)
               ▲                                   ▲        ▲
               └────────── agent 全量调度 ──────────┘        │
                                          教师改判/确认（判卷中心页）┘
```

### P1 · 判卷中心（核心，1-2 周）

**新建 `app/services/grading_center.py`**（由 `llm_grading.py` 深化更名/重组）：

```python
grade(entries: list[AnswerEntry], key: AnswerKey) -> list[QuestionResult]
    # AnswerEntry: {question_ref, raw_answer}  ← 来源无关
    # 分层：归一化精确匹配（选择/判断）→ 非选择题批量 LLM 语义判定 ≤1 次
save(results, student_id, exam_record_id, source: online|ocr|manual|chat) -> None
    # 单点写 StudentAnswer；按 record.type 定生效策略（练习即生效 / 考试待确认）
    # 幂等：answer_id 去重；写后 enqueue diagnosis（练习）或挂确认队列（考试）
override(answer_id, is_correct, reason, teacher_id) -> None   # 改判 + 重触发该生诊断
confirm(exam_record_id) -> None                              # 考试批量确认 → save 生效
finalize(exam_record_id) -> Stats                            # 真均分/分布，替换 exam.py:177 TODO
```

**改造点**：
- `POST /api/practice/submit` 尾部改调 grading_center（选择同步判；主观题 enqueue Celery「语义判卷」作业）
- `agent/tools/ocr_grading.py`：`grade_answer_sheets`/`save_grading_results` 变薄 adapter；`save_grading_results` 的落库体搬进 service；新增 `query_grading_queue(teacher_id)`
- `app/api/ocr.py:616`（/stats 粘贴判卷）尾部统一到 save，barrier 结果落库
- `app/services/ocr_service.py:214`（correct_edu 路径）尾部统一到 save
- `app/services/wrong_question_trainer.py:224`：训练作答补 `source=training` 标记
- 前端 `OcrSheetsPage.tsx` 升格判卷中心：新增「待判队列」（主观题 LLM 结果+考试确认）与「线上提交」（逐生逐题浏览+override）tab

### P2 · 练习分发（1 周）

**新建 `app/services/assignment_service.py`**：

```python
assign(targets, source: Adaptive(kps?, count) | Bank(set_id) | Manual(question_ids),
       name_hint) -> AssignmentResult[] | AssignmentBatch
    # 内部：compose（Adaptive: ZPD+生成+四维机器闸+重生成；Bank/Manual: 取题）
    #       persist（逐生 ExamRecord(PRACTICE)+Question，不再 [:5] 裸截断）
    #       batch_split（>5 人 → Celery 逐生作业，student_id 幂等）
    #       notify_hook（→ P3 dispatch）
progress(batch_id) -> BatchProgress
```

**改造点**：
- `agent/tools/diagnosis.py:596` `assign_adaptive_practice` 变薄 adapter，返回真实逐生结果（record_id、题数、审核摘要）；异步批返回 batch_id
- 新增 agent 工具 `query_assignment_progress(batch_id)`
- `POST /api/practice/assign` 变薄（service 的 HTTP adapter）
- 删 `app/api/question.py:1148`（smart-assign）、`:1295`（batch-assign，消除偷题行为）
- `app/scheduler/daily_practice.py` 改调 service（Bank 来源随机 N 题，消灭空卷）

### P3 · 学生触达（3-4 天）

- 新表 `StudentNotification`（id, student_id, type, payload JSON, read_at, idempotency_key UNIQUE）
- NotificationService 补 `dispatch(recipient, event, idempotency_key)`：站内写 StudentNotification / ParentNotification；可配置开关下经 chemistry_notification 网关（Discord/Slack/Telegram/Email）外发——skill handler 改为调统一分发 REST（ADR-0012 单向依赖）
- `GET /api/notification/student/{id}/notifications` 真实现（替 stub）；修/删 4 个假路由
- `frontend/m/app.js`：练习 tab badge（拉取未读数）
- 触发点：assignment_service.notify_hook、grading_center 判卷完成、周报

### P4 · 考试生命周期（1 周，依赖 P1）

- `ExamRecord` 加 `status` 列（迁移：`question_stats.published=True → published`，其余 → draft）
- 转移规则：`publish→published`；学生开考→`in_progress`；判卷中心有结果→`grading`；`confirm 全量/finalize→completed`（finalize 用 grading_center.finalize 的真统计）
- 学生作答（4.2）：`GET /api/practice/student/{id}/tasks` 按 status 过滤（考试只出现在 published/in_progress）；`PracticeTask` 补 `title`/`type` 字段（学生端区分考试与练习）；m/practice.html 支持主观题输入（文本域）与「主观题待判定」态
- exam router 维持 teacher-only（ADR-0009）

### P5 · 对话作答回流（2-3 天，依赖 P1）

- `StudentAnswer` 加 `source` 列（online | ocr | manual | chat | training）
- `agent/tools/tutoring.py` `_make_tutor_tool`：步骤作答判定后调 grading_center.save(source="chat")；`chemistry_tutor` 不捕获（自由问答不入库）
- 诊断作业读侧不变（自然吃到 chat 作答）；后续如需降权，按 source 过滤即可

## 五、测试策略（interface 即测试面）

- assignment_service：合成学生 + 假 LLM——三 source 各一条 compose 断言、机器闸重生成断言、批次切分与幂等断言
- grading_center：归一化匹配表驱动用例 + 语义判定 fake LLM + save 幂等 + override 重触发诊断 + 练习/考试两档生效
- agent 工具层：只测「转发正确 + JSON 形状」（薄壳测试，不测业务）
- 闭环 e2e：布置→作答→判卷→诊断回流→周报读到新数据

## 六、依赖与风险

- 顺序硬依赖：P4 依赖 P1（grading 态/finalize）；P5 依赖 P1（save 路径）；P2/P3 并行可行
- Alembic 迁移三张：ExamRecord.status、StudentNotification、StudentAnswer.source（存量回填：online）
- LLM 语义判卷成本：沿用「≤1 次/卡」批量判定约束到线上提交（按一次提交批量）
- 风险：m/practice.html 主观题 UI 是学生端最大前端增量；先支持文本域，公式编辑器不做
