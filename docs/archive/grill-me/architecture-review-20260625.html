Candidate 1: Triple Prompt-Routing Stack

Strong
agent/gateway.py agent/langgraph_agent.py agent/channel/langgraph_channel.py

Problem

User intent traverses three independent LLM calls — Gateway classifier → Coordinator routing → Sub-agent tool selection. Each layer reformulates the same question through a different prompt. Each layer doesn't share state about what the prior decided. One layer misses → whole chain fails silently.

The Gateway's _keyword_fallback already classifies tools well, but this classification is discarded after tool narrowing. Coordinator re-decides from scratch. Sub-agent re-decides again.

Solution

Collapse Gateway + Coordinator into one step. One LLM call produces (intent, target_agent, suggested_tools). Pass as structured state through the graph. Coordinator becomes deterministic. Make Gateway's keyword fallback the primary router — LLM only for ambiguous inputs.

After: 1 LLM call + deterministic dispatch

  K -->|ambiguous| L["Single LLM: intent+agent+tools"]
  K -->|matched| D2[Deterministic Dispatch]
  L --> D2
  D2 --> E2[Sub-agent: receives hints]
  E2 --> F2[tool call]

Benefits

  • Locality: One module owns intent → agent → tool mapping.
  • Testability: Keyword router is 100% deterministic. LLM has clear interface.
  • Leverage: Keyword fallback already exists, just needs to be promoted.

Candidate 2: Prompt Rules Duplicate Tool Docstrings

Strong
agent/langgraph_agent.py:246-255 agent/tools.py (all docstrings)

Problem

Each sub-agent has 2-4 tools with excellent docstrings ("何时用", "会发生什么", "下一步"). But prompts duplicate this as hand-written numbered rules. These are always incomplete. "我有几个班" doesn't match any rule — yet the tool's docstring covers it. Each new user expression = new prompt rule. Unsustainable.

"1. 具体学号 → diagnose_barrier(student_id=学号) 2. 问有哪些学生 → show_students 3. 班级名+学生 → show_students"

Solution

Delete hand-written rules. Trust the tools. Replace with:

你必须调用一个工具。阅读每个工具的描述来决定用哪个。 不确定时，选择最可能相关的工具并调用它。 禁止在不调用工具的情况下直接生成回复。 show_students 无参数时列出所有班级。

LangGraph passes tool descriptions to the LLM via function-calling API. The LLM can read them — the current prompt prevents it.

Candidate 3: No Fallback at the Sub-Agent Layer

Worth exploring
agent/langgraph_agent.py:159-228 agent/gateway.py:191-238

Problem

The Gateway has a solid _keyword_fallback. Sub-agents have no fallback. When the LLM doesn't call a tool, whatever text it generates becomes the response — no safety net.

Solution

Add a deterministic post-check in create_sub_agent_node: if no tool was called, run keyword matching and force-call the best-matching tool. Reuses Gateway's keyword patterns.

Candidate 4: Shallow Output Contract Enables Tool Skipping

Worth exploring
agent/langgraph_agent.py:153-156

Problem

_SUB_AGENT_OUTPUT_CONTRACT says "严禁闲聊" but doesn't say "MUST call a tool." LLM satisfies contract by generating terse JSON without calling any tool. The contract prohibits bad output but doesn't mandate good behavior.

Solution

Rewrite as positive constraint:

你必须先调用至少一个工具。工具返回后，基于 result 输出。 如果 tool 返回 error，原样输出 error 文本。 如果 tool 返回 _component，不要输出额外文字。 严禁跳过工具调用直接生成回复。

Candidate 6: Gateway Hints Are Discarded in LangGraph Path

Speculative
agent/channel/langgraph_channel.py:88-96 agent/langgraph_agent.py:337-364

Problem

The Gateway classifier produces tool_names and intent, but these are only used for navigate shortcut. In the LangGraph path, hints are built as a string but the coordinator never injects them. Gateway's classification is silently discarded — the Coordinator re-classifies from scratch.

Solution

Pass Gateway results as structured shared_context in initial graph state. Coordinator skips LLM routing when Gateway has high-confidence results. Sub-agents receive tool hints directly.
