# ChemAI（智辅化学）AI 产品岗位面试题库

> 适用场景：学员以 ChemAI 项目经验应聘 AI 产品经理 / AI 产品运营 / 大模型应用产品岗位
> 设计原则：每道题都是面试官看着简历会问的问题，不是对着文档的背诵检查

---

## 一、项目总览（面试必问的开场）

### Q1 介绍一下这个项目是做什么的？

**参考答案：**

ChemAI 是一个给高中化学老师用的 AI 教研助教。老师把学生答题卡拍照上传，系统自动批改、诊断每个学生错在哪里、然后根据诊断结果自动出针对性练习题。

做这件事的原因很简单：一个化学老师带 150 个学生，批改一次作业要 6 小时，根本没时间给每个学生做个性化诊断。我们的系统把这个流程压缩到 45 分钟，而且能告诉老师"李雨萱不是化学不会，是她老在审题上踩坑"。

现在在湖南 3 所种子学校跑着，66 个学生，积了 9600 条答题数据，诊断采纳率 82%。

---

### Q2 你为什么选化学这个领域？又不是热门赛道。

**参考答案：**

三个原因：

第一，化学是 AI 最容易出错也最需要垂直验证的学科。化学式配平，通用大模型能做到 80-85% 准确率，但对老师来说一个配不平就是教学事故。这个"不可接受的错误率"就是壁垒。

第二，化学老师少但刚需强。一个学校语文老师十几个，化学老师就三五个，但新高考化学是选考科目，老师对"精准教学"的需求比主科更迫切——他们没有那么多人手分工。

第三，竞品少。数学赛道已经卷成红海了，化学几乎没人专门做。与其在红海里卷，不如在一个小赛道上做到第一。

---

### Q3 你在这个项目里具体负责什么？

**参考答案：**

（这题因人而异，根据学员实际角色调整。以下是参考框架）

我负责三块：
- **产品设计**：从市场调研、用户访谈到 PRD、信息架构、权限体系、14 个页面的设计规格
- **Agent 行为设计**：意图识别怎么分层、Planner 怎么拆任务、Persona 怎么配工具权限、GuardState 怎么设护栏
- **评测体系**：14 维度 111 个场景的测试用例设计，从"路由准确率"到"跨角色越权"

代码是和 AI（Claude Code）协作生成的，我出 prompt 和验收标准。

### Q4 这个项目现在什么阶段？有人用吗？

**参考答案：**

Pilot 阶段（种子验证）。3 所湖南的高中在用，3 个老师、覆盖 66 个学生。跑了 13 次考试、9600 条答题记录、324 道题库。

核心指标：诊断采纳率 82%，批改时间从 6 小时降到 45 分钟（降了 87.5%）。月度 LLM 成本不到 200 块。

下一步目标是扩展到 10 所学校，验证不是"创始人关系驱动"而是"产品价值驱动"。

## 二、产品设计与决策（面试官追问"你怎么想的"）

### Q5 为什么第一版不做学生端、不做家长端，只做教师端？

**参考答案：**

因为我们验证了一个假设：教师是飞轮的发动机。

学生端的 MAU 只有教师端的 1/3——学生不会主动看诊断报告，他们只看分数。但教师会主动用，因为省时间是他们的刚需。

所以先让教师用起来 → 教师把诊断结果推给学生 → 学生在教师的引导下使用 → 教师用量越大，数据越多，诊断越准，口碑越好。

这是典型的 B2B2C 路径：教师是入口，学生是终端，家长是付费方。先搞定入口，再往下渗透。

---

### Q6 你们的竞品是谁？差异化是什么？

**参考答案：**

没有直接竞品，但有替代品：讯飞做批改、小猿做搜题、学科网做题库组卷、通用大模型做对话。

我们的差异不在功能层面，在理念层面：没有人做"从诊断到出题的闭环"。

讯飞能告诉你"这道题学生答错了"，我们告诉你"他答错是因为把氧化剂和还原剂搞反了，这是概念理解障碍，不是粗心"。然后自动出一套针对这个障碍的练习题。

通用大模型也能出题，但它的方程式 15-20% 配不平。我们的四维审核引擎把配平做到了 100% 准确——因为那不是靠 AI，是靠程序算的。

---

### Q7 出题系统具体怎么做的？

**参考答案：**

三种模式：按知识点出题（老师讲完氧化还原反应，要 5 道课堂练习）、按试卷结构出题（出一份月考卷）、按学生弱点出题（李雨萱在离子方程式和化学平衡上有障碍，针对这两个点出变种题）。

技术链路是 RAG 增强：先从知识图谱拿该知识点的前置知识和常见迷思 → 向量检索 ChromaDB 找最相似的 20 道真题 → 去重（相似度 >0.85 的去掉、知识点覆盖要多样） → LLM 基于参考题 + 迷思规则生成变种题 → 四维审核引擎扫描 → 通过后输出。

最难的是去重这一步——没有它，AI 可能给学生连出 3 道考同一个点的题，表面不同，实质一样。

---

### Q8 四维审核引擎是怎么保证出题质量的？

**参考答案：**

四个维度：系数配平（权重 40%）、反应条件（25%）、产物稳定性（20%）、分子结构（15%）。

系数配平是程序化验证，不是靠 LLM。解析方程式 → 提取左右两边所有原子 → 逐个计算总数 → 不相等就退回 LLM 修正，最多重试 3 次。这一步能做到 100% 准确。

反应条件和产物稳定性靠"14 类条件规则库 + RDKit 化学信息学验证"。

但说实话，反应条件和产物稳定性这两维做不到 100%，所以输出时带置信度标记：>0.9 直接通过，0.5-0.9 标黄提醒教师复核，<0.5 不返回给学生。教师端有审核模式，一键通过/修改/拒绝。

---

### Q9 三维障碍诊断模型是什么？怎么想到的？

**参考答案：**

跟一线老师访谈发现的。老师说"学生错题不是简单的'不会'两个字能概括的"。

我们拆成三种：
- **概念理解障碍**：真不会，氧化剂还原剂搞反了——约占 45%
- **审题障碍**：会，但题目问"不正确的一项"他没看到"不"字——约占 30%
- **表述障碍**：会，也看懂了，但方程式忘了写△加热标记——约占 25%

这个分类的价值在于"精准干预"——你不能对三种不同原因的错用同一种补救方式。概念障碍要补微课，审题障碍要练审题策略，表述障碍要纠正规范习惯。

数据是我们从 9600 条答题记录里跑出来的分布，不是拍脑袋。

---

### Q10 自适应练习和传统"全班统一发卷子"有什么区别？

**参考答案：**

理论基础是维果茨基的最近发展区（ZPD）——太简单没效果，太难以放弃，要刚好在"够一够能够到"的区间。

我们的做法：根据学生诊断出的掌握水平，算一个 ZPD 区间 [当前水平 + 0.5σ, 当前水平 + 1.5σ]，只推这个区间内的题目。连续 3 题正确上调难度，连续 2 题错误下调难度。

种子学校数据：用自适应练习的学生，相同知识点后续测试正确率比统一练习的高 18%。

本质差别不是技术，是理念——统一练习是"以教师为中心"（一起发省事），自适应是"以学生为中心"（每个人练自己需要的）。

---

### Q11 间隔复习不就是 Anki 吗？你们有什么不一样？

**参考答案：**

机制上确实像 Anki，艾宾浩斯 5 级状态机：1 天 → 3 天 → 7 天 → 14 天 → 30 天，连续 2 次正确升级，错一次就降级。

但本质区别是"谁决定该复习什么"。Anki 靠学生自己判断"这题我会了"——学生通常会严重低估遗忘程度。我们的系统是诊断数据驱动的——学生上次在离子方程式上錯了几次、现在掌握到什么程度、什么时候该复习，系统说了算。

而且复习的不是原题，是同一知识点的变种题，防止学生记住答案而不是理解知识。

---

### Q12 学情预警系统怎么设计的？为什么不做排名？

**参考答案：**

三种预警：连续 5 天未登录、连续 3 次排名下降 >10%、某知识点连续 5 题错误。

预警阈值是可配置的——重点班老师觉得下降 5% 就该关注，普通班觉得 20% 才需要关注。不给固定阈值。

关于排名：只显示学生"相对于自己的变化趋势"，不做班内排名公开显示。这不是技术问题，是产品价值观问题——我们服务的是学习过程，不是制造焦虑。排名带来的攀比和挫败感对一个学习工具来说是负资产。

---

## 三、Agent 架构设计（面试官最想聊的部分）

### Q13 你们的 Agent 架构是怎么设计的？为什么这么选？

**参考答案：**

现在是 v2：单 LangGraph ReAct Agent + Gateway 预分类。之前 v1 是个多 Agent 架构，Coordinator 分发到 6 个专家 Agent，路由准确率只有 70-75%，经常把"出题"分到"搜索"，而且上下文跨 Agent 传递损耗严重。

v2 改成单 Agent 配 30 个工具，Agent 通过工具 docstring 自己选工具，路由准确率到了 85%+。原则是"让 Agent 自己判断比替 Agent 判断准确"。

单 Agent 的问题是工具太多时可能选错——用 Persona 过滤解决。教师看到 25 个工具，学生只看到 13 个，家长只看到 8 个。在设计层面阻断比在 prompt 里写"不要用"可靠。

---

### Q14 Agent 调用一个请求的完整链路是什么样的？

**参考答案：**

用户输入 → Gateway 预分类（LLM + 关键词双通道，判断意图 + 推荐工具 + 选 LLM Provider）→ 注入 GuardState（去重/次数限制/前置条件/审批门禁/递归上限）→ Agent Think → 选工具 → 调用工具 → 拿到结果 → 再 Think → 再选工具... 直到任务完成或达到 12 次递归上限 → SSE 流式输出给前端。

SSE 分 6 个阶段：thinking → tool_call → tool_result → reply → navigate → done。用打字机效果而不是一次性返回 JSON，因为教育场景中教师等待时的感知体验很重要——流式输出 2 秒感觉像 1 秒，JSON 一次返回 1 秒感觉像 5 秒。

---

### Q15 意图识别怎么做的？

**参考答案：**

四层分层：

第一层关键词直接拦截——"谢谢"、"好的"、闲聊这种不进 Agent，省成本，秒回。

第二层 LLM 语义理解——判断是 chat 还是 navigate，推荐 top 3 工具，选 LLM Provider（图片走 MiMo，文本走 DeepSeek）。

第三层自检——槽位满了没有？比如"出题"意图，知识点/题型/数量/难度缺了任何必填字段就不往下走。

第四层多轮补全——缺了什么槽位就问什么，最多问 3 轮，第 4 轮直接用默认值填。每轮最多问 2-3 个问题，不搞"一次性列出 8 个问题让老师填"。

如果 LLM 挂了走关键词 fallback（30+ 规则），关键词也匹配不上就走全工具兜底——Agent 看到所有工具自己判断。三层降级保证基本可用。

最终叠加效果：意图识别准确率 >95%，P99 延迟 <1.2s。

---

### Q16 如果意图识别错了怎么办？

**参考答案：**

分四种情况处理：

意图模糊（"帮我弄一下那个"）→ 追问 + 提供快捷按钮，降低输入成本。

意图完全识别不了（乱码/方言）→ 关键词 fallback → 关键词也匹配不上 → 全工具可用兜底，让 Agent 自己理解。不在 Gateway 层直接拒绝用户。

话题切换（出题流程中老师说"等一下，先看李雨萱上次成绩"）→ MemoryStack 检测话题切换 → 清空当前槽位 → Gateway 重新识别。

LLM 服务完全不可用 → 纯关键词模式，UI 显示"AI 服务暂时降级"。

---

### Q17 复杂任务怎么拆？比如老师说"检查李雨萱情况、生成周计划、顺便出几道题"

**参考答案：**

Planner 拆成 4 步：

Step 1：查李雨萱诊断档案（diagnose_barrier）——拿到弱点、成绩趋势、错题统计。

Step 2-3（并行）：一边根据诊断结果生成学习周计划，一边走"提取弱点→索引知识图谱→索引题库→去重聚合→出题"链路。

Step 4：汇总输出。

关键设计：步骤间有依赖管理（拿到诊断数据之前不执行后续步骤）、结果可引用（`${step_1.diagnosis}`）、最多 6 步、有循环检测、某步失败则依赖它的步骤跳过并输出已完成部分。

如果 Planner 自己解析失败了怎么办？降级为单步执行——Agent 直接处理，不拆。

---

### Q18 Persona 系统怎么设计的？为什么要分角色？

**参考答案：**

同一个 Agent，教师能看到出题工具，学生不能——这不是 prompt 里写"不要出题"能保证的，prompt 约束是软的，LLM 可能绕过。

做法是代码层硬过滤：每个工具标注 `personas: ["teacher"]`，加上 YAML 配置白名单，取交集。学生说"帮我出几道题"，Agent 看到的工具列表里根本没有 generate_questions，它就自然地引导去做自适应练习。

四个角色：teacher（25 工具）、student（13 工具）、tutor（19 工具）、parent（8 工具）。

YAML + TOOL_META 双重过滤的原因：YAML 让非技术人员可以改（比如给家长开放诊断查看），TOOL_META 是代码级兜底（即使 YAML 配错了也不会越权）。

---

### Q19 安全方面做了什么？

**参考答案：**

GuardState 五层：

1. 去重：同一工具 + 同一参数 + 5 秒内跳过，防止 Agent 不确定"上次调了没"而重复调用
2. 次数限制：每个工具每次对话最多 5 次，总计最多 50 次，防止死循环
3. 前置条件：出题前必须先有搜索/诊断结果，条件不满足返回"请先执行 XXX"
4. 审批门禁：高风险操作（批量推送练习、删除题库、发通知）需要教师确认
5. 递归上限：12 次 Think-Act 循环后强制结束

关键是在代码层拦截，不是 prompt 层——prompt 约束可以被 LLM 绕过，代码不会。

---

### Q20 记忆系统怎么做的？上下文太长怎么办？

**参考答案：**

三层记忆：Working Memory（滑动窗口 20 轮，当前会话）、Episodic Memory（关键事件摘要，跨会话，存 LangGraph SqliteStore）、Student Profile（学生画像，持久化，数据库 + ChromaDB）。

上下文管理双策略：TrimMessages（超过 20 轮的只保留 tool_call 和 tool_result，裁剪 think 过程；超过 50 轮的只保留摘要）和 LLM 摘要压缩（超过 64K tokens 时压缩前一半对话为 500 字摘要）。

上下文管理不是为了省 token 钱，是保证 Agent 决策质量——窗口太长，陈旧信息会干扰 Agent 判断。

---

### Q21 LLM 成本怎么控制在 200 块一个月的？

**参考答案：**

五层策略：
- Gateway 分流，简单任务走便宜的 DeepSeek，省 40%
- 关键词直接拦截闲聊，不进 LLM，省 10-15%
- 相同题库查询 1 小时内缓存复用，省 20%
- trim_context 主动压缩减少 token，省 15-20%
- 非核心场景（补全槽位、简单判断）用小模型，省 10%

四级 fallback 保证可用性（MiMo → DeepSeek → Qwen → GLM），成本策略保证经济性。

## 四、工程与评测（面试官试探你的技术深度）

### Q22 技术栈怎么选的？为什么不选更主流的方案？

**参考答案：**

核心原则：够用就好，但每项都有升级路径。

选 FastAPI 不选 Django 因为 Django 太重，不选 Flask 因为不支持 async。选 LangGraph 不选 CrewAI/AutoGen 因为前者更灵活，后者太重。选 ChromaDB 不选 Pinecone 因为免费且 SQLite 在 MVP 阶段够用。前端用 Vanilla JS + Tailwind CDN 不选 React 因为一个人维护不了构建工具链。

每一项都是"当前阶段的最简可行方案 + 明确的升级路径"（SQLite → PostgreSQL，单容器 → 多实例，ChromaDB → 更成熟的向量数据库）。

---

### Q23 评测体系怎么做的？

**参考答案：**

14 维度、111 个场景，分三层：Baseline（路由准确、工具调用、工作流、行为约束，25 场景）、Boundary（极端情况、错误恢复、工具结果利用、规划一致性、状态转换，31 场景）、Regression（跨角色权限、SSE 流、一致性、性能、已知缺陷，30 场景），再加 5 个端到端工作流。

86 项确定性测试 5 秒跑完做 CI 门禁，36 项 API 测试 PR review 前跑，5 项端到端发版前手动触发。

核心方法论是评测先行——先写好"什么样的输出算合格"，再写代码，跑通测试算完成。不是写好功能再补测试。

这个很重要，因为 AI 产品的行为是不确定的，没有测试用例你根本不知道改了一个 prompt 会不会搞坏 10 个其他场景。

---

### Q24 你们用 AI 写代码（Vibe Coding），代码质量怎么保证？

**参考答案：**

Vibe Coding 不是"随便说一句就出代码"。三件套：OpenSpec 把模糊需求转化为精确 spec → Claude Code 按 spec 写代码 → GStack 跑评测验证。

四是 CLAUDE.md 体系：全局偏好 → 项目架构 → 模块设计决策 → 当前任务上下文，四层上下文确保 AI 生成的代码符合项目规范。

但最核心的质量保证还是评测。86 个测试用例跑一遍，代码质量有客观验证，不是靠"我觉得代码写得还行"。

## 五、商业化与增长（面试官关心你是不是只懂产品不懂商业）

### Q25 怎么赚钱？

**参考答案：**

B 端为主：学校按教师数付费，标准版 3000 元/师/年，高级版（含家长端+学情预警）5000 元/师/年。

定价锚定"一个学生一学期补课费 2000-5000 元"——一个老师服务 100+ 学生，花 3000 提升教学效率，账算得过来。

走"信息技术试点经费"而非"教学经费"渠道，前者预算更灵活、审批链更短。

C 端是未来：家长端 99 元/月看孩子的学情周报。但现阶段先 B 后 C，因为学校是更稳定的收入来源。

### Q26 怎么进学校？教育产品的销售很难。

**参考答案：**

走自下而上：先让一两个老师免费用 → 老师觉得好用 → 教研组长向上汇报 → 学校买单。

不走自上而下（直接找教育局/校长），因为在没有口碑的时候，行政命令推不动。

3 所种子学校都是这个路径进去的。优势是决策链短（老师→组长→副校长），劣势是慢（一个学期以上）。

增长飞轮的核心不是广告投放，是教研会口碑——化学教研员在省教研会上推荐一次，胜过 100 次电话推销。

## 六、AI 产品经理方法论（面试官评估你是不是真的理解 AI PM）

### Q27 做这个项目最大的挑战是什么？

**参考答案：**

不是技术，是"怎么让 AI 的行为可预期"。

传统产品你写"点击按钮→弹窗"，行为是确定的。AI 产品你说"配一下方程式"，AI 可能配平、可能乱写、可能开始讲氧化还原理论。

解决方式就三条：评测体系（111 个场景量化"什么叫好"）、约束性 prompt + docstring（精确告诉 Agent 什么该做什么不该做）、降级兜底（AI 不行的时候有没有人工路径）。

本质是 AI PM 需要多一套技能：行为设计 + 评测设计 + 降级设计。

---

### Q28 AI 产品经理和普通 PM 到底有什么不同？

**参考答案：**

三个核心差异：

普通 PM 写"点击按钮→弹窗"，AI PM 面对的是"用户说一句话→AI 可能做十种不同的事"。评测体系从锦上添花变成生存必需品。

普通 PM 设计功能和流程，AI PM 设计 Agent 的行为——docstring 写得好不好直接决定 Agent 聪不聪明。

普通 PM 可以说"功能上线了"，AI PM 得说"功能上线了，准确率 95%，幻觉率 <2%"。AI 产品的功能不是二进制的工作/不工作。

---

### Q29 你怎么向一个不懂技术的人解释 Agent 架构？

**参考答案：**

就像一个新来的实习老师。你给他一本教师手册（system prompt），告诉他能用哪些工具（30 个工具 docstring），什么样的问题能用什么工具（NOT for 边界）。

然后学生来问问题，他先自己想一想（Think），决定用哪个工具（Act），用完之后看结果（Observe），再想一想要不要用下一个工具（Think again）。

有时候他会"想太多"——同一件事来回做。所以我们设了上限：最多想 12 次，超过就强制给结果。有些重要操作（比如通知家长、删题库内容）需要先找班主任确认——这就是审批门禁。

---

### Q30 如果重新做这个项目，你会做什么不同的决定？

**参考答案：**

第一，学生端不会做那么早。花了很多时间做了 4 个学生端页面，但学生根本不会主动用。应该在教师端验证稳了之后再投入学生端。

第二，Planner 应该更早接入主流程。现在 Planner 是设计好了但实际使用中很多走的是 Agent 自己拆——不够标准化。

第三，search_exam_bank 一开始就该支持 SQLite 查 AI 保存的题。现在只读 JSON，AI 生成的题搜不到，是个技术债。

## 七、压力测试（面试官故意刁难）

### Q31 你这不就是套壳吗？有什么壁垒？

**参考答案：**

底层 LLM 是第三方的，这我不否认。

但壁垒不在模型，在四个地方：化学四维审核引擎（方程式配平 100% 准确，不是靠 prompt，是程序算的）、22 条化学迷思规则（基于教学经验+考试数据+学术文献的领域知识库）、诊断→出题→练习的数据闭环（越用越准，新来的没有这个积累）、111 个场景的评测体系（竞品得把坑全踩一遍）。

说套壳是"只用 LLM 做一层薄封装"，我们是 "LLM + 领域验证 + 知识库 + 数据闭环 + 评测体系"——LLM 是发动机，但车上还有变速箱、刹车、导航。

---

### Q32 你们化学式配平不准怎么办？老师用一次发现错误就不用了。

**参考答案：**

对，这是致命问题。我们的处理是四层防线：

系数配平是程序化验证，100% 准确。反应条件和产物稳定性 LLM 判断，带 confidence score——低于 0.9 标黄提醒教师复核，低于 0.5 不返回给学生。

教师端有审核模式，每题显示四维审核结果（✅/⚠️/❌），可修改或拒绝。学生用完后可以反馈"这道题有问题"——反馈数据回传给出题系统。

本质思路：AI 生成不是终点，人工审核+反馈闭环才是。

---

### Q33 你怎么证明这个产品有价值？又不是大厂做的。

**参考答案：**

数据：种子学校 3 所，老师批改时间从 6 小时降到 45 分钟，降了 87.5%。AI 诊断采纳率 82%——意思是每 100 次诊断，老师认可 82 次。

但比数字更重要的是一个场景：张老师，高三化学备课组长，以前出一份针对性练习要花一个下午——翻错题本、翻教辅书、手打出题。现在 20 分钟搞定，每道题旁边还标注了"这道题针对你们班哪些薄弱知识点"。她现在开备课组会直接用系统出的题，其他老师问"题哪来的"，她就推荐。

数字证明量，故事证明质。

---

### Q34 团队风险怎么办？

**参考答案：**

这是真实风险。我从三个方面降低了它：

文档极全——从市场分析到 PRD 到代码上下文，任何有 Python+LangGraph 经验的工程师读 2 周文档能接手。评测自动化——86 个测试用例跑一遍就知道有没有搞坏。架构极简——单 Agent+单库+单容器，维护成本低。

而且当前阶段 1 个人反而是优势——PMF 验证期需要的是快速迭代，不是大团队协作。规模化阶段才需要扩张。

---

### Q35 为什么不直接用 ChatGPT？老师直接问 ChatGPT 不也能出题吗？

**参考答案：**

你试试让 ChatGPT 给你学生出一份化学月考卷。它出的题可能配不平、可能超纲、可能去年高考刚考过原题。更关键的——它不知道你的学生李雨萱在离子方程式上卡了 8 次，它不会说"第 3 题专门针对李雨萱的概念障碍"。

通用大模型缺三样东西：专业验证层（方程式配平）、学生数据上下文（这个人哪里弱）、教师工作流集成（OCR 批改→诊断→出题→练习一连串）。

---

### Q36 如果现在有个公司抄你，3 个月上线，你怎么办？

**参考答案：**

3 个月能抄走 UI 和功能列表，抄不走四样东西：

22 条迷思规则——这是跟一线教师聊了很长时间积累的隐性知识。111 个评测场景——是踩了一整年的坑。3 所种子学校的信任关系和 9600 条真实答题数据——数据闭环没有捷径。化学四维审核引擎——抄得了 prompt，抄不了 14 类条件规则库和 RDKit 验证代码。

功能可以 3 个月赶出来，但一个"化学教学问题解决不了"就足够让老师卸载了。

## 八、行为面试（面试官评估软素质和思维方式）

### Q37 老师和学生对产品反馈最不好的地方是什么？

**参考答案：**

学生端的诊断报告。我们写的诊断结论是"概念理解障碍"、"审题障碍"这种术语——教师能看懂，学生一脸懵。

学生只看分数，不看原因。所以学生端 MAU 只有教师端的 1/3。

如果重来，我会把诊断结果翻译成学生语言："你可能把氧化剂和被氧化的概念搞反了，建议做以下 3 道练习。"而不是"检测到概念理解障碍 type-A"。

---

### Q38 你和开发（或者你和 AI）意见不同时怎么办？

**参考答案：**

（这题根据学员实际情况调整）

和 AI（Claude Code）协作时，它有时会过度设计——我想加个 20 行的功能，它写了 200 行还加了 3 个抽象层。我的原则是：先让它写，然后要求"用最简方式实现，去掉不必要的抽象"。

核心是需求方（我）保持判断力——AI 是执行者，不是决策者。知道"什么是够了"比知道"怎么做"更重要。

### Q39 你对这个产品 3 年后的想象是什么？

**参考答案：**

三年后不只是一个化学出题工具。

是做"每个化学老师上课前看一眼就知道今天该讲什么、每个学生拿到的是针对自己弱点的练习、每个家长看到的是真实进步而非焦虑营销"。

从化学起步，验证模式后可以扩展到物理、生物——因为这些学科都有"方程式需要验证"、"实验条件需要审核"的共性。

但前提是先把化学做透。扩展之前先做到 100 所学校跑通，PMF 验证扎实。
