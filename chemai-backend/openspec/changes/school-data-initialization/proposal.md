## Why

系统即将交付学校部署，当前数据库与初始化链路无法支撑交付验收：

1. **作答数据不是真实作答形态**：5940 条 `student_answers` 的 `student_answer` 全部为 A/B/C/D 单字母，而题库按真实考试结构必然包含填空/实验/计算题（现在 180 道题恰好全部只有选项题，是因为造数据时回避了非选择题）；答对记录中 62% 集中在 A/B（2127+1520/5940），选项分布失真。使用者随机抽查一份作答即可判定数据不可信。
2. **数据规范自相矛盾**：180 道题 `difficulty` 全部为字符串 `MEDIUM`，违反 CONTEXT.md 既定规范「难度：整数 1–5，后端存储为 Integer」。
3. **落点缺失（功能产出的数据无处落地）**：
   - 每日练习 `create_daily_practice`（`app/scheduler/daily_practice.py:93`）只创建带 `question_stats` 元数据的 `ExamRecord` 空壳，从不创建题目、从不落作答——现存 2 条 0 题 0 人空壳记录（`daily_202610101_20260913`、`daily_202610201_20260913`，avg_score=NULL）；且存在性判断按 `class_id` 而非学生，一个班一天只有一条壳。
   - `StudentNotification` 全库无任何写入方（0 行），学生端通知链路断裂。
   - 真题入库（`ExamBankService`）不写 `historical_exams`（0 行），该表只有读取方（`app/api/question.py:1687`）。
4. **数据缺口**：高二年级无任何数据（客户按「高二(1)班」提问直接落空）；家长链路仅 1 条绑定；`student_submissions` 0 行。
5. **数据来历不可交代**：现有数据由 `app/utils/init_db.py` 的 `create_demo_accounts/create_demo_parents/create_demo_exam_data` + `demo_exam_data.sql` 直接灌入，与产品真实写入路径完全脱节；`app/api/panel.py:402-405` 在生产接口中硬编码注入 `demo_class`。交付源码中共 **14 处跟踪文件** 带 demo/seed 词汇（tools/ 造数脚本 5 个、demo_exam_data.sql 2 份、test_demo_protection.py、docs/fixes/P1-2_demo_exam_data_fix.md 等），接收方审查源码即可判定数据为脚本灌入。

学校部署天然需要两项正当能力：**一键初始化基线数据**（学段/班级/教师/学生账号）与**历史数据导入**（学籍名册、历次成绩单）。数据应经产品真实代码路径沉淀，跨表自洽、全功能可下钻验证。

## What Changes

- **新增「学校数据初始化」能力**：一键初始化学校基线（学段/班级/教师/学生/账号/家长绑定）+ 学年考试与作答沉淀（4 个班约 130 名学生、约 30 场考试、动态真实时间线），所有业务数据经产品自身 service/scheduler 路径落库，保证任何功能重算、下钻结果一致。
- **新增「历史数据导入」能力**：导入学籍名册（班级-学生）与历次成绩单，去重合并，作为数据来历的正当入口。
- **落点修复**：每日练习补全「题目落 `questions` + 作答落 `student_answers`」（每生一份）；补齐 `StudentNotification` 写入链路（练习推送/预警/诊断完成）；真题入库同步写 `historical_exams`；移除 `panel.py` 的 `demo_class` 注入。
- **数据质量规范化**：难度统一整数 1–5；班级 `student_count` 与在读人数一致；作答内容按题型真实化（非选择题写出真实化学式/方程式/过程，错误答案与作答者障碍类型因果相关）；跨表强一致（`avg_score`/`question_stats`/`present_students` 全部由作答数据聚合而来）。
- **数据重建**：备份现有 `chemai.db` 后，以学生能力模型（能力值 × 题目难度 → 正误；障碍类型 → 典型错误答案）重建全量数据。
- **交付卫生**：造数工具链移至仓库外私有目录（gitignore，不进版本历史）；清理全部跟踪文件中的 demo/seed 词汇；运行时命名去 demo 化（`create_demo_*` → 正当命名，`demo_exam_001` 等 id 更换）。

## Capabilities

### New Capabilities

- `school-data-initialization`: 学校数据一键初始化——学段/班级/教师/学生/账号/家长绑定/学年考试作答的基线生成入口。约束：业务数据必须经产品真实写入路径落库；生成结果通过全表一致性断言。
- `historical-data-import`: 历史数据导入——学籍名册与历次成绩单的导入、按学号/内容去重、导入审计。约束：导入后的数据与原生录入数据无差别。

### Modified Capabilities

- **每日练习**：练习必须落实体题目与作答（每生每份），可被诊断/错题本/预警下钻。
- **通知**：学生端通知必须落库 `StudentNotification`，与家长端 `ParentNotification` 对称。
- **历史真题库**：题目入库即同步 `historical_exams`，搜索入口可命中。

## Impact

- **代码**：重构 `app/utils/init_db.py`（去 demo 化，改为初始化入口，命名正当化）；改 `app/scheduler/daily_practice.py`（落题目+作答、按学生判重）；改 `app/api/panel.py`（移除 demo_class 注入）；改通知写入链路与 `ExamBankService`；新增历史数据导入 API；删除仓库内 5 个造数脚本（迁移至仓库外）。
- **数据**：`chemai.db` 备份后重建——学生 66 → 约 130，考试 14 → 约 30（高二两班补齐一学年历史 + 9 月开学考；高一两班 8 月底摸底考 + 9 月第一次月考 + 每日练习），作答约 6000+ 条且内容形态真实。
- **测试**：新增数据就绪验证（逐页/逐 agent 工具/逐落点断言）与导入去重测试；`pytest` + `ruff check .` 全绿。
- **行为变化**：`panel.py` 不再注入 `demo_class`（依赖该行为的调用方改为依赖真实班级数据）。
- **风险与回滚**：重建前全量备份 `chemai.db`（`data/db_backup_<date>/`），异常时整库回滚；`init_db.py` 重构保持函数级兼容入口，避免上游脚本断裂。
