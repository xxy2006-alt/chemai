# 对话作答回流 — 设计决策

> 来源：grilling（2026-09-12）。教学决策为代定（用户未逐项作答，按「全量实现」指令采用），标注可推翻。

## 决策 5.1（代定，可推翻）：捕获 + 计入诊断，不降权

选项：捕获并计入 / 捕获但不计入（仅存档）/ 不捕获。

采用**捕获并计入**：分步导学工具每步有明确的预期答案，对错可结构化判定，数据质量不低；对话是学生最高频练习触点，不纳入则学情长期缺一大块。「不降权」的理由是诊断作业当前无权重机制，先等权纳入，`source` 列保留后续按来源调权的实现余地（无需数据迁移即可调整读侧）。

若推翻（教学上认为对话作答不应影响诊断）：读侧按 source 过滤即可，捕获数据不受影响。

## 实现要点

- 捕获点只在**分步导学工具**（六大专题 tutor）：每步学生作答 → 工具内判定 → `grading_center.save(source="chat")`。
  幂等键实现为「学生×题目×作答内容摘要」（channel 未向工具暴露会话ID；跨会话同题同答视为同一作答事件）。
  判定依据 expected_answer 由 agent 在工具调用时给出（模型可知教材答案）；学生身份由服务端
  contextvars 注入（对齐 set_current_teacher 先例），模型无法伪造身份，expected_answer 只影响判定质量。
- 自由问答（chemistry_tutor）不捕获：无结构化预期答案，判定无依据。
- 落库的作答关联 question 为该步题目引用；exam_record_id 为空（学生作答记录本就允许为空，与错题训练同形态）。

## 测试决策

- 分步工具薄壳测试：作答 → 判定 → save 调用参数（source=chat、幂等键稳定）。
- 端到端一条：对话完成若干步 → 诊断聚合结果包含 chat 作答的贡献。
- 重放幂等：同一会话同一步重放不重复落库。

## Out of Scope

- 对话作答的权重机制（source 列就位后属读侧调参，另行）。
- chemistry_tutor 自由问答的隐式错题发现。
- 对话内练习的判分结果即时反馈 UI（工具回复文本已有提示语）。
