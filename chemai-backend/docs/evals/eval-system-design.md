# ChemAI Agent 评估体系设计（v2）

> 2026-08-15 grilling 会话产出。替代旧的「基线/边界/回归」三分法。
> 决策记录见 `docs/adr/0007-agent-eval-system.md`。

## 1. 目标（按优先级）

1. **发布门禁** — 每次更新前跑，不合格就拦下
2. **质量度量与趋势** — 持续跑、出趋势，回答「Agent 变好还是变差」
3. **指导迭代** — 发现蠢场景/薄弱点，驱动开发（评估先行）
4. **对标同行** — 二期接外部 benchmark

## 2. 七层评估模型

| 层 | 评估什么 | 机制 | 运行层 | 现状 |
|---|---|---|---|---|
| **L0 工具自身正确性** | 每个工具干得对不对（read 编码/路径穿越、edit 精确替换、bash 沙箱逃逸/危险命令） | 确定性断言 | 快跑 | 有雏形（`evals/test_unit_tools.py`），新工具待写 |
| **L1 行为轨迹** | 该用哪个工具、参数对不对、顺序对不对 | 确定性断言（tool_called/tool_arg） | 快跑 | 有（golden yaml），扩管理类动作 |
| **L2 输出与交互质量** | 五族判官 rubric（见 §3） | LLM-as-judge + rubric 打分 | 慢跑 | 无 |
| **L3 安全护栏** | prompt injection、角色越权、危险操作审批、bash 沙箱逃逸 | 对抗语料 + 断言 | 慢跑 | 只有 isolation |
| **L4 性能预算** | 延迟、token、循环数 SLO | 阈值断言 | 快跑 | 无（软警告起步） |
| **L5 稳定性回归** | 快照 diff、防静默退化 | 快照对比 | 快跑 | 有 |
| **L6 端到端任务** | 完整任务成功率 | 场景剧本 + 成功判定 | 慢跑 | 无 |

## 3. L2 判官库（五族 rubric）

| 族 | 判官评什么 |
|---|---|
| 出题 | 化学正确性（权重最高）+ 难度匹配 + 解析正确 + 格式规范 |
| 判卷 | 每题判分对错（vs 黄金答案） |
| 诊断 | 障碍类型判断（concept/reading/expression） |
| 方案 | 学习计划/干预方案适配性、可执行性、个性化 |
| 交互智能 | 澄清追问、主动推荐、给选项引导、拆解与进度 |

**判官设计**：
- 判官用**备选 provider**（qwen/deepseek），避免与被评模型自评偏差；上线前**实测判官能力**（真题 vs 官方答案）。
- **校准**：每族 20-30 条标注样本，判官 vs 人工一致率 ≥80% 才启用；出题/判卷族用真题官方答案，诊断/方案族用项目历史数据，交互智能族用真实「蠢场景」翻译的 golden 场景。
- **兜底（人机混合）**：判官低置信度/低分的样本自动抽出人工复核，只有判官自信的部分才自动计入门禁。
- **成本预算**：慢跑层单次判官调用 ≤200 次，约 ¥2-5/次（月度预算 ¥500 内可控）。

## 4. 快/慢双层运行

- **快跑层**（每次更新/提交，秒级，零 LLM 成本）：L0 + L1 + L4 + L5
- **慢跑层**（夜间/发布前，分钟级，花 token）：L2 + L3 + L6

## 5. 门禁策略

- 快跑层 **100% 必须绿**（确定性断言，挂了就是真挂了）。
- 慢跑层：**严重错误一票否决**（化学错误、安全问题、端到端失败 → 拦发布）；**分数只做趋势**（判官分数有噪声，不发门禁）。

## 6. 评估先行（eval-first）工作流

> 评估即 spec。先写评估（定义「什么算好」，此时全红）→ 再开发到绿 → 分数涨 = 开发进度。

对每个开发项：先把它的评估场景写出来（红）→ 开发 → 绿 → 进快/慢跑层常驻。

## 7. 开发路线（评估先行，按序）

**A. 补齐基础工具四件套**（pi agent 同款理念）
- `read` / `write` / `edit` / `bash`（bash **沙箱化**：限工作目录、白名单命令）+ 辅助 `find`/`grep`
- L0 评估先行：read（编码/路径穿越/敏感文件拒绝）、edit（精确替换/找不到明确报错）、bash（沙箱逃逸/危险命令/超时）
- L3 同步扩：bash 注入、危险命令拦截

**B. 出题智能化**
- 交互智能 golden 场景先行：「我要出题」→ 必须追问题型/难度/知识点 + 按班级薄弱点推荐（当前只会机械开工作台）
- 开发：persona/prompt 增强 + 薄弱点上下文注入

**C. 接线现有 planner + 步骤进度 UI**
- `agent/planner.py` 已实现但零引用（死代码，openspec agent-planner-layer 产物）
- L2 交互智能「拆解与进度」场景先行：复杂任务应产出步骤计划并汇报进度
- 开发：planner 接入 v2 agent + 前端步骤 UI

## 8. 术语表

- **快跑层 / 慢跑层**：按成本与耗时分的两层运行模式
- **判官（LLM-as-judge）**：用 LLM 按 rubric 给 agent 输出/交互打分的评估机制
- **rubric 库**：按能力族组织的打分标准集合
- **校准集**：人工标注的样本集，用于验证判官一致性
- **黄金场景（golden scenario）**：输入 + 期望行为的评估用例
- **评估先行（eval-first）**：先写评估再开发的流程
