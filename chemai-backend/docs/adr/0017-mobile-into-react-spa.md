# 移动端（学生/家长）并入教师端 Vite React SPA

三端原是"教师端 React SPA + 移动端零构建静态 HTML（frontend/m/*.html，每页内联样式）"的混合形态，导致三套视觉语言并存、鉴权/API/KaTeX 等逻辑重复、无类型无测试。2026-09 视觉升级时决定：不做"旧 HTML 换肤"，而是把学生端与家长端并入同一个 Vite React SPA（`/m/` 路由段 + 移动布局壳），重构与重设计一次完成。选此方案是因为迁移对象仅约 2600 行薄逻辑（fetch + SSE + sessionStorage 鉴权），且教师端已有可复用的 api 客户端、ChatPage SSE 消费层、antd 与 vitest 基建，边际成本低；而继续在静态 HTML 上换装等于给零类型零测试的代码再打一层补丁。

## Considered Options

- **仅换肤不动架构**（否决）：最快（约每端 1-2 天），但三套皮肤问题固化，未来迁移时新样式需重写。
- **移动端独立第二 SPA**（否决）：两个应用两套部署，比现状更散。

## Consequences

- 后端 `/m/{filename}` 静态路由改为重定向兼容旧 URL，SPA 托管 `/m/` 前缀路由。
- 现有移动端 e2e 脚本（`_e2e_verify*.py` 等）选择器需同步更新。
- 移动端页面与教师端共享 `tokens.css` 体系，但主题按端作用域隔离（学生深色 / 家长浅色互不渗漏）。
