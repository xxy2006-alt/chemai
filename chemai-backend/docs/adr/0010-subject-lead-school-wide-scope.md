# 学科组长的数据范围是全校 × 本学科

权限设计文档 5.2 / 5.3 给学科组长写的是"本学科/本班范围"——这两个词自相矛盾，定不下这位组长到底能看多少。这个角色存在的意义是横向对比各班的教学质量：如果范围只到自己任教的班，学科组长就只剩"能多做几个操作"，没有任何范围差异，角色本身失去价值。

我们决定：**学科组长的数据范围是全校 × 本学科**。化学学科组长能看到全校所有班级的化学数据，哪怕那些班不是他教的。

**Status**: accepted

**Considered Options**

- **全校 × 本学科**（选中）：符合"教研组长"的实际职务，跨班横向对比才有意义。
- **仅自己任教的班**：范围与普通任课教师一致，学科组长只剩操作差异。否决——这会架空这个角色。

**Consequences**

- 学科组长的"学科"来自 `teacher_class_subject.subject`，**不在角色上**。换学科、换班只改关系表，不动角色定义。
- 数据范围整体从关系表推导（`teacher_class_subject` → class → `grades.school_id`），角色只决定用哪几个维度去收窄。这条规则适用于所有员工角色，不只学科组长。
- `classes.teacher_id` 是死字段（两行全 NULL，API 无写入路径，前端零引用）；真实师生关系只走 `teacher_class_subject`，其 `is_class_teacher` 才是班主任标记。
