# Agent 评估体系：七层模型 + 判官 + 评估先行

ChemAI 此前用「基线/边界/回归」三分法零散组织评估，缺少答案质量（LLM-as-judge）与工具自身正确性两层，且评估无法指导 agent 能力开发。决定采用**七层评估模型**（L0 工具 / L1 轨迹 / L2 判官质量 / L3 安全 / L4 性能 / L5 回归 / L6 端到端），快/慢双层运行；L2 判官用备选 provider 并配「低置信度人工复核」人机混合兜底；开发流程改为**评估先行**（eval-first，评估即 spec），驱动 A（基础工具四件套）/ B（出题智能化）/ C（planner 接线）三项开发。详见 `docs/evals/eval-system-design.md`。

Status: accepted

## Considered Options

- **维持三分法 + 零散补充**：否决——没有判官层就无法评估答案质量与交互智能，也无法度量「agent 聪不聪明」。
- **慢跑层分数线门禁**：否决——判官分数有噪声易误拦；改为严重错误一票否决 + 分数只做趋势。
- **先开发后评估**：否决——改为评估先行，避免「功能做完但没有可测目标」的模糊开发。
- **判官与基准同模型**：否决——自评偏差；改用备选 provider（实测能力，不足则人机混合兜底）。

## Consequences

- L2 判官依赖备选 provider 的能力，须先用真题实测；不足时走人机混合兜底（低置信度人工复核）。
- 校准集需要整理：出题/判卷族用真题官方答案，诊断/方案族用项目历史数据，交互智能族用真实「蠢场景」翻译。
- 慢跑层有 token 成本（单次约 ¥2-5），在 ¥500/月预算内可控。
- L0 层是唯一全确定性层，每次更新必跑，是门禁的第一道闸。
