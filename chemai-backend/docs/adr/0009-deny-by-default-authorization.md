# 授权默认拒绝，按 APIRouter 声明

全库 234 个端点，做角色或归属判断的只有 20 个（8.5%）；75 个连令牌都不需要，139 个只要有任意有效令牌。设计好的 `require_permission` 装饰器、`require_auth`、`get_teacher_classes` 数据范围函数都写好了，**全仓库零端点调用**。根因不是"有人写错了检查"，而是**没写检查不会报错**——默认放行，漏掉永远是静默的。

我们决定改为默认拒绝：每个 `APIRouter` 在注册时声明基础权限，端点只在特权动作上覆盖；漏声明即 403，写代码的人当场发现。

**Status**: accepted

**Considered Options**

- **默认允许，逐点加 `PermissionChecker`**：渐进、风险低、可改一个测一个。否决——漏掉的端点永远没人发现，正是当前这个局面。
- **默认拒绝，234 个端点逐个显式声明**：最严格，每个端点都有人签字。否决——234 处样板会淹没 diff，改造期噪音过大。
- **默认拒绝，router 级声明 + 端点级覆盖**（选中）：`app/api/` 下一个文件基本就是一个资源，router 即模块，21 条声明代替 234 条，粒度天然对齐代码结构。混合权限的文件（如 `question.py`）在 router 声明 `question:read` 基线，approve / delete 在端点覆盖。
- **默认拒绝的代价**：改造期间会出现大量 403，必须一次把一个 router 做完，不能半途。

**Consequences**

- 新增端点忘记声明权限 → 403，而非静默开放。
- 必须配一条完整性测试：断言每个已注册端点都在权限表里有登记，否则测试失败。这条守卫是这个决策能长期成立的前提。
- 权限表本身成为权限的活文档——比写文档可靠，因为它会跑。
