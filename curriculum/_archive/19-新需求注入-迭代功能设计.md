# 19 · 新需求注入 — 迭代功能设计

## 教导主任的变种真题需求（3 月中旬提出）

### 1. 需求来源与优先级升级

**提出人**：邵阳县第一中学教导主任（通过种子教师转达）

**提出时间**：3 月 15 日

**原始表述**："能不能把历年真题改成不同版本让学生练？同一次考试不同考场需要多套等价试卷。"

**优先级变更**：P2 → P1（行政力量推动，从远期规划提升到当前迭代）

**需求性质分析**：
- 这不是一线教师的需求——教师不会主动提"多套等价试卷"
- 这是考试管理者的需求——月考/期中考试命题阶段，多个考场需要等价但不同的试卷防作弊
- 表面是"出题"需求，实质是"防作弊 + 省时间"需求

### 2. 场景拆解

**When**：月考/期中期末考试命题阶段（每 3-4 周一次）
**Who**：教导主任推动 → 教师执行
**What**：选一道真题作为蓝本 → 生成 3-5 个同考点、同难度、同题型的变种
**Pain**：人工出多套等价试卷耗时 1-2 天
**Expect**：选蓝本 → AI 一键生成变种 → 教师审核 → 直接可用

### 3. 技术方案设计

**方案**：在现有 `generate_questions` 工具中增加 `variant_source` 参数

```python
# agent/tools.py:generate_questions(variant_source=exam_id, ...)
# variant_source 不为空时进入变种题模式：
# 1. 从题库取出蓝本题
# 2. 提取考点/难度/题型
# 3. LLM 生成同构变体（保持考查目标不变，替换表层信息）
```

**四条红线**（与种子教师确认，不可违反）：
1. 化学方程式系数不能变——变了系数就是不同反应
2. 反应条件不能变——加热/催化剂/通电/点燃必须一致
3. 产物不能变——NaCl 不能变 KCl，Fe₂O₃ 不能变 Fe₃O₄
4. 考查知识点不能变——氧化还原的题不能变离子反应的题

**可以变的部分**：
- 题干情境："工业制硫酸" → "实验室制硫酸"
- 数据：浓度 0.1mol/L → 0.2mol/L
- 选项顺序：选择题 A/B/C/D 打乱
- 干扰项：换一个新的常见错误选项（如把 Na₂CO₃ 换成 NaHCO₃）
- 气体/试剂种类：SO₂ 换 CO₂（但要确保化学性质逻辑一致）

**前端变种题浏览器**（`frontend/js/agent.js:1127-1155`）：
- v1（3 月初）：点一下选中 + 关闭 → 单选，不可逆
- v2（3 月 29 日）：Toggle 多选模式 + "✕ 清除蓝本"按钮 + "确认蓝本"按钮 + 选中计数

- 变种题和普通出题走同一个审核流程（`chemical_balance` 四维审核）

### 5. OpenSpec 变更管理

对应 OpenSpec 变更提案目录：
```
openspec/changes/
├── inline-exam-workbench/    # 内联出题工作台（含变种题入口）
├── agent-exam-workbench-integration/  # Agent 不再直接出题，跳转工作台
└── agent-inline-panels/      # 内联面板体系（含出题面板）
```

关键设计决策（来自 `agent-exam-workbench-integration/proposal.md`）：
- Agent 不直接调用 `generate_questions`——会编造进度幻觉
- 改为 `show_exam_workbench` → 跳转出题工作台 → 用户在 UI 中配置参数
- 变种题作为出题工作台的子功能，走相同的内联面板机制

### 6. POC 验证计划

**测试蓝本题**：2020 年全国卷 T3（气体除杂，知识点：氧化还原反应）

**POC 脚本逻辑**（伪代码，完整实现在 `agent/tools.py:generate_questions`）：
```python
# 1. 读蓝本题
source = exam_bank_service.get_by_exam_id(variant_source)
# 2. 构造 Prompt（含四条红线约束）
prompt = f"基于真题 [{source.exam_id}]，生成 3 个变种..."
# 3. 调 DeepSeek
result = llm_service.generate_text(prompt=prompt, temperature=0.3, max_tokens=2000)
# 4. 审核
for q in result:
    audit = chemical_balance(q.content)
    if audit.errors: reject
```

**验证清单**：
| # | 验证项 | 通过标准 |
|---|--------|---------|
| 1 | 生成 3 个变种 | Python 脚本返回 3 个有效 JSON 题目 |
| 2 | 无化学式错误 | `chemical_balance` 零 block 级别错误 |
| 3 | 保持考查本质 | 种子教师盲测 ≥2/3 被判为"等价" |
| 4 | 速度可接受 | ≤15s/变种 |

### 8. 风险与缓解

| 风险 | 概率 | 缓解 |
|------|------|------|
| LLM 变种题质量不稳定 | 中 | 四维审核 + 教师盲测 ≥2/3 等价 |
| 教师认为变种不够"等价" | 中 | 迭代 Prompt + 增加约束直到通过 |
| 教导主任要求支持含图题 | 低 | 当前 scope 为纯文本题，图片变种放下一迭代 |
| 已有功能回归 | 低 | `evals/run_evals.py` 全量回归测试 |
| 复习中心进度莫名消失 | 已修复 | pydantic-ai 单轮调用不支持多步骤 |

### 9. 与原有功能的关系

变种题不是独立功能——它复用了三个已有模块：
1. `search_exam_bank`：从题库中查找蓝本题
2. `generate_questions`：已有出题能力，只需加 `variant_source` 参数
3. `chemical_balance`：已有审核能力，变种题同步审核

新需求 = 旧模块的新参数组合。这是 ChemAI 迭代的核心理念。
