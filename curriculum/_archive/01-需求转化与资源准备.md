# 01 · 需求转化与资源准备

## 项目起点：2026 年 1 月

ChemAI 项目的起点不是技术选型，是在邵阳县第一中学一位化学教师的办公室对话。

### 1.1 种子教师画像（真实数据）

#### 1.1.1 为什么不是学校统一采购？

种子教师的付费意愿是个人付费（月付 50-100 元），而不是学校采购。原因：
1. 学校采购流程长（一学期），个人付费即时
2. 教师希望工具是自己的，不受学校 IT 部门管控
3. "帮我完成行政上报的工具，我第一天就绕过去"——教师极度排斥被学校监控

这个洞察决定了产品设计方向：教师端优先，学校端可选。不做学校管理后台，不做强制登录。

### 1.3 1 月第一周的真实工作流

**Day 1（1 月 7 日）**
- `mkdir chemai-backend && cd chemai-backend`
- `pip install fastapi uvicorn sqlalchemy python-dotenv httpx pydantic`
- `app/main.py:1-30`：第一个路由 `@app.get("/")` → `{"status": "ok"}`
- `app/core/config.py`：环境变量 `CHEMAI_PORT=8001`、`DEEPSEEK_API_KEY` 写入 `.env`
- 提交 `892ce30 v1.0.0: 初始版本`

**Day 2（1 月 8 日）**
- `app/services/llm_service.py:60-99`：`generate_text()` 方法
- Provider 优先级链：MiMo → DashScope → DeepSeek（三路 fallback）
- 第一条测试："配平 Fe + O2 = Fe2O3" → DeepSeek 返回 `4Fe + 3O2 = 2Fe2O3` ✅
- `app/services/llm_service.py:114-134`：`ocr_image()` Qwen-VL-OCR 方法

**Day 3（1 月 9 日）**
- `app/services/ocr_service.py`：Baidu OCR 集成（`_call_baidu_ocr` 函数）
- 第一次测试：拍高考化学试卷图片，识字率约 80%，但化学式全丢
- 结论：Baidu OCR 只适合快速预览，不适合正式导入

**Day 4-5（1 月 10-13 日）**
- 第一轮用户访谈：角色扮演式，输出 3000 字访谈记录
- 核心发现：错题统计 1.5h/次、AI 出题后需验题 30min/次、90+ 人班无法个性化

**Day 6-7（1 月 14-15 日）**
- 评审 + 调整方向
- `ChemAI开发计划_20260422.md`：确定 MVP 功能优先级
- 决定先做错题统计 + AI 出题审核，其他放后续

### 1.4 技术预研里程碑

**LLM 选型预研（1 月第 2 周）**
- 10 道覆盖六大板块的化学测试题，逐个 Provider 实测
- DeepSeek-V3：20/20 分（全对）→ 主力
- MiMo-V2.5：20/20 分但联网搜索有时效性问题 → 备用视觉
- DashScope Qwen：18/20 分（漏写反应条件）→ 三级 fallback

**OCR 引擎选型预研（1 月第 3 周 → 2 月切换）**
- Baidu OCR（`app/services/ocr_service.py`）：快但化学式丢失 → 预览用
- Qwen-VL-OCR（`app/services/llm_service.py:ocr_image`）：慢且 LaTeX 碎片化 → 放弃
- MinerU v3.4 pipeline（`import_mineru_paper.py`）：完整保留 LaTeX+表格+图片 → 最终方案

**Agent 架构预研（2 月 → 3 月最终确定）**
- v1（2 月初）：pydantic-ai 单轮调用 → 不支持多步骤工具链，路由不稳定
- v2（2 月中）：LangGraph ReAct Agent → 单个 Agent 拿 14 个工具 → 路由准确率 60%
- v3（3 月初）：LangGraph Multi-Agent StateGraph → 1 协调器 + 6 子专家 + Gateway 关键词预路由 → 路由准确率 100%
