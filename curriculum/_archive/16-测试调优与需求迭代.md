# 16 · 测试调优与需求迭代

## 不是测试方法论，是这个项目实际改了哪些 bug、怎么发现的、怎么修的

### 问题 1：2020 年真题只导出 6 道题（2026-06-25）

**发现**：用 Baidu OCR + LLM 导入 2020 全国卷，JSON 里只有 6 道题

**根因**：Baidu OCR 对化学式识别率极低，`$\mathrm{H_2SO_4}$` 被识别为 `H2SO4` 纯文本。LLM 拿到碎片化文本后无法正确分题

**修复**：OCR 管线从 Baidu API 迁移到 MinerU pipeline。2020 卷从 6 题 → 12 题完整

**代码变更**：`import_exam_papers.py`（Baidu 方案，废弃）→ `import_mineru_paper.py`（MinerU 方案）

### 问题 2：前端公式和图片不渲染（2026-06-28）

**发现**：考试工作台的历史真题页面，`$\mathrm{SO_2}$` 显示为原始 LaTeX 文本，图片不显示

**根因**：`renderChem` 函数用了 `marked.setOptions()`，但这在 marked v12 中已废弃。整段崩溃回退到纯文本渲染

**修复**：改为 `marked.parse(text, {breaks:true, gfm:true})`；LaTeX 块先用占位符保护，再用 KaTeX 渲染

**代码变更**：`frontend/pages/exam-v2.html:627`（renderChem 函数）+ `frontend/js/agent.js:952`（renderChemistry 函数同步修复）

### 问题 3：加入考试后题目不显示（2026-06-29）

**发现**：从真题库选题 → 加入考试 → 考试列表查看 → 0 题

**根因**：API 返回 `exam_id` 但前端读的是 `question_id`。`question_id` 在 API 响应中不存在 → `undefined` → 后端找不到题目

**修复**：在 `app/api/exam_bank.py:485` 加一行 `"question_id": q.exam_id`

### 问题 4：Agent 对话历史丢失（2026-06-29）

**发现**：服务重启后对话记录消失

**根因**：`MemorySaver` 只在内存中保存，进程被杀即丢

**修复**：`MemorySaver` → `SqliteSaver` → 不支持 async → `AsyncSqliteSaver` → `asyncio.run()` 冲突 → 最终方案：懒加载

**代码变更**：`agent/langgraph_agent.py:16-24`

### 问题 5：学生端对话显示为空（2026-06-29）

**发现**：学生登录后对话区域空白

**根因**：`scrollBottom()` 函数滚动了 `#chat-messages`，但 overflow 在父层 `.chat-area`

**修复**：`el = document.querySelector('.chat-area') || document.getElementById('chat-messages')`

**代码变更**：`frontend/js/agent.js:762`

### 问题 6：联网搜索说"截至 2024 年"（2026-06-29）

**发现**：问 2026 年的考试信息，MiMo 回答"截至 2024 年，2026 年尚未到来"

**根因**：MiMo 的 `enable_search` 搜索确实执行了，但模型在系统 prompt 影响下追加了训练数据截止声明

**修复**：改为 Bing HTTP 直搜 → DeepSeek 总结。不经过 MiMo

**代码变更**：`agent/tools.py:web_search` 函数重写，增加 Bing HTTP 作为首选

### 问题 7：变种题蓝本不能多选/清除（2026-06-29）

**发现**：变种题蓝本选择器只能单选，选了不能去

**根因**：原代码的 `click` 事件直接设置 `panel._variantQid` 并关闭弹窗——单选 + 不可逆

**修复**：改为 toggle 多选模式 + 添加"✕ 清除蓝本"按钮 + 确认蓝本按钮

**代码变更**：`frontend/js/agent.js:1127-1155`（变种题 browser 重写）

### 问题 8：MinerU 模型下载失败（2 月 15 日）

**发现**：`import_mineru_paper.py` 运行报 `OSError: Can't load the configuration of PP-DocLayoutV2`

**根因**：MinerU 的 7 个 pipeline 模型只下载了 MFR（公式识别），缺 Layout、OCR、Table 等 6 个模型

**修复**：
- 尝试 1：`huggingface-cli download` → 被墙，0MB
- 尝试 2：ModelScope `snapshot_download` → 速度 300KB/s
- 尝试 3：开 VPN 用 HuggingFace → 全量 187 文件，约 20 分钟
- 尝试 4：发现仍有 3 个模型缺失，写 `download_mineru_models.py` 逐个补

**代码变更**：`download_mineru_models.py`（临时的模型下载脚本，后清理）

### 问题 9：Windows multiprocessing 崩溃（2 月 15 日）

**发现**：`test_mineru_2020.py` 报 `RuntimeError: An attempt has been made to start a new process...`

**根因**：MinerU pipeline 内部的 `ProcessPoolExecutor` 在 Windows `spawn` 模式下重新 import 主模块，导致无限递归

**修复**：加 `if __name__ == '__main__':` 保护 + `multiprocessing.freeze_support()`

**代码变更**：`test_mineru_2020.py` → 所有顶层代码移入 `main()` 函数

### 问题 10：chromadb + numpy 2.0 冲突（2 月 20 日）

**发现**：`from app.services.llm_service import llm_service` 报 `AttributeError: np.float_ was removed in NumPy 2.0`

**根因**：chromadb 依赖 `np.float_`，numpy 2.0 移除了这个别名

**修复**：`pip install "numpy<2.0"`

### 问题 11：前端 scrollBottom 滚错元素（3 月 28 日）

**发现**：对话超过一屏后，新消息不自动滚动到底部

**根因**：`scrollBottom()` 函数（`frontend/js/agent.js:762`）滚动了 `#chat-messages`，但 CSS overflow 在父层 `.chat-area`

**修复**：
```javascript
var el = document.querySelector('.chat-area') || document.getElementById('chat-messages')
```

### 问题 12：agent.js 浏览器缓存（3 月 28 日）

**发现**：改了 agent.js 但前端不生效——`agent.js?v=14` 版本号没变

**根因**：浏览器基于版本号缓存，版本号不递增就不会重新加载

**修复**：每次改 agent.js 后递增版本号（现在用的是 `?v=21`）

### 问题 13：AsyncSqliteSaver 四次尝试（3 月 29 日）

已在文档 08 POC 中详述。补充：这个问题的解决花了 4 次尝试、约 2 小时。每次尝试都需要重启服务、测试、看日志。

### 问题 14：Persona 不生效（3 月 29 日）

**发现**：前端传了 `persona: "teacher"`，但 chemistry_tutor 仍用学生模式回答

**根因**：LLM 调用工具时传 `persona="tutor"`（默认值），覆盖了 `_current_persona`

**修复**：
1. `agent/langgraph_agent.py` 加 `_current_persona` 全局变量
2. `agent/tools.py:chemistry_tutor` 加 fallback：`if persona in ("", "tutor", "auto"): persona = _current_persona`
3. 子专家 prompt 改为动态编译（用 `_current_persona` 判断）

### 问题 15：renderChem 中 marked.setOptions 崩溃（3 月 28 日）

已在文档 16（原问题 2）中详述。补充：这个 bug 的表现是**静默失败**——不报错、不白屏、不崩溃，只是公式永远不渲染。是一个典型的"API 版本兼容性导致的功能降级"案例。

### 测试调优的工作流

```
发现问题（用户反馈/开发者自测）
  ↓
复现问题（构造同样的输入条件）
  ↓
定位根因（读代码 + 看日志 + 加 debug print）
  ↓
修复（改最小范围代码）
  ↓
验证（跑 evals/test_langgraph_agent.py + 手动 E2E）
  ↓
部署（git commit + uvicorn reload）
```

每个问题的修复时间从 10 分钟（#3 加一行 JSON 字段）到 2 小时（#4 对话持久化 4 次重试）不等。
