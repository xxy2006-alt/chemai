### 教师端 6 页面

**1. `frontend/index.html`（AI 教研助手主页）**

行数：约 250 行。核心技术：SSE 流式对话 + 侧边栏 + 用户信息。

SSE 流式的实现细节（`agent/channel/langgraph_channel.py:37-172`）：
- `StreamingResponse` + `media_type="text/event-stream"`
- 需要 `X-Accel-Buffering: no` 头——否则 nginx 会缓冲 SSE 导致前端收不到事件
- 心跳帧：每 15s 发一个 `data: [PING]\n\n`，防止代理超时断开
- `[DONE]` 帧：流结束标志，前端据此关闭连接

**2. `frontend/pages/exam-v2.html`（考试工作台）**

行数：917 行（项目最大单文件）。技术：Vue 3 CDN + 内联。

4 个 Tab 的实现：
```javascript
sourceMode: 'ai',  // 'ai' | 'bank' | 'history' | 'exam'
```
- `ai`：AI 出题工作台（默认）
- `bank`：题库管理（列表 + 编辑 + 删除）
- `history`：历史真题库（2020-2025 + 图片渲染）
- `exam`：考试列表（创建 + 添加题目 + 发布）

**3. `frontend/pages/students.html`**：学生管理（教师端查看/添加/搜索）

**4. `frontend/pages/teacher.html`**：班级学情面板（成绩图表 + 趋势分析）

**5. `frontend/pages/diagnosis.html`**：障碍诊断（选班级 → 选考试 → 展示障碍分布）

**6. `frontend/pages/ocr.html`**：答题卡识别（上传 PDF/图片 → OCR → 展示结果）

### 共享模块 app.js

`frontend/m/app.js`（约 130 行）的四个导出函数：

```javascript
function getUser()      // sessionStorage → 用户对象
function requireAuth()  // 无登录态 → 跳转 /m/login.html
function api(url, opts) // fetch + token 自动注入
function renderTabBar() // 底部 4 Tab 导航（纯 JS 生成 DOM）
function renderHeader() // 顶部标题栏
```

不做 SPA 的原因已经在文档 05 中写了——但这里补充一个具体数字：`app.js` 130 行 + 每个页面平均 200 行 = 总前端代码约 1300 行。如果用 React + Redux + React Router，同样的功能至少 3000 行起步。

**学生专用登录**：`/m/login.html`（移动端优化）

### 后端路由实现

`app/main.py` 的路由设计：
```python
@app.get("/")              → frontend/index.html (教师主页)
@app.get("/login.html")    → frontend/login.html
@app.get("/pages/{name}")  → frontend/pages/{name}.html
@app.get("/m/{name}")      → frontend/m/{name}.html (学生端)
@app.get("/m")             → RedirectResponse("/m/index.html")
```

`/m/` 路由是 2026-06-29 新增的——之前学生端不存在，不需要这个路由。

### 教师端 exam-v2.html 的 Vue 3 架构（917 行详解）

整个项目最复杂的单文件，用 Vue 3 CDN + 内联实现 4 个 Tab。

**数据模型**（行 481）：
```javascript
modal: {
  show, fading, title, message, type: 'confirm',
  _manageTab: 'paper',      // 考试管理的子 Tab
  _vbStep: 'dir',           // 变种题浏览器的步骤
  _vbPapers: [],            // 试卷列表
  _vbQuestions: [],         // 题目列表
  previewLoading: false,
  previewQuestions: null,   // 考试预览题目
}
```

**4 个 Tab 的实现**（`sourceMode` 变量驱动）：
- `'ai'`：出题工作台（AI 生成 + 手动录入 + 变种题）
- `'bank'`：题库管理（列表 + 编辑 + 删除）
- `'history'`：历史真题库（按年份/区域筛选 + 图片渲染 + 加入考试）
- `'exam'`：考试列表（创建 + 添加题目 + 发布 + 管理）

**关键交互**：
- 出题 → `aiGenerate()`（行 661）：调 `POST /api/question/generate`
- 保存 → `saveOne(i)`：逐题保存到题库
- 真题加入考试 → `addHistToExam()`（行 845）：多选 → 选考试 → `POST /api/exam/{eid}/questions`
- 考试管理 → `manageExam()`（行 882）：预览题目 → 删除题目 → 发布考试

**渲染管线**：
```
renderChem(q.content)  →  LaTeX 保护 → marked 解析 → KaTeX 渲染
  ├── 处理 Markdown 表格
  ├── 处理 ![](figures/...) 图片
  ├── 处理 $...$ 行内公式
  └── 处理 $$...$$ 块级公式
```

### exam-v2.html 的已知问题

1. 917 行单文件过大，部分逻辑（变种题浏览器、考试管理）可以拆成独立组件
2. `renderChem` 和 `agent.js` 中的 `renderChemistry` 是两份独立实现，应该合并
3. 4 个 Tab 的数据在页面打开时一次性加载（不需要懒加载），但如果题库超过 1000 题需要分页

### 前端性能的实际数字

| 指标 | 数值 |
|------|------|
| 首页加载（首次）| ~500ms（含 CDN 脚本）|
| 首页加载（缓存）| ~50ms |
| 对话延迟（首 token）| ~2s（DeepSeek API）|
| 对话延迟（后续 token）| ~50ms/token（SSE 流式）|
| 考试工作台加载 | ~300ms（Vue 3 内联） |
| 学生练习页加载 | ~200ms |
| 前端 JS 总体积 | <50KB（不含 CDN 依赖） |

不做性能优化的前提是：用户量 <5 个教师 + <200 个学生。没有并发问题需要考虑。
