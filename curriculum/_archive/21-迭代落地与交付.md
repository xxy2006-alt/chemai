### 3. 交付流程

```
代码完成 → 自测通过 → 种子教师试用 → 收集反馈 → 迭代 → 稳定 → OpenSpec 关闭
```

不是一次交付就完。种子教师每 1-2 周试用一次，每次反馈产生新的修复或功能需求。

**实际的一次迭代交付循环**（变种真题功能）：
```
3/15 教导主任提出需求 → 3/15-16 POC 验证 → 3/17-20 前端集成 →
3/22 教导主任演示 → 3/23-25 迭代修复 → 3/29 前端多选+清除完成 → 交付
```

### 4. 交付质量标准

**代码**：
- `python -m uvicorn app.main:app` 无错误启动
- 关键逻辑有中文注释说明意图
- 每个功能对应一个 OpenSpec 变更提案
- Agent 路由准确率 100%（20/20 Golden 场景）

**文档**：
- OpenSpec 三个文件（proposal/design/tasks）必须完整
- tasks.md checkbox 全部打勾
- 课程文档有代码路径 + 实际数据 + 用户反馈

**产品**：
- 种子教师实际使用并给出反馈（不是"理论上能用"）
- 无已知 P0/P1 blocking bug
- 6 个核心 E2E 场景全部通过

### 5. 迭代节奏

ChemAI 采用非正式迭代——没有固定的 Sprint。节奏由以下因素决定：

| 触发因素 | 迭代频率 | 实例 |
|---------|---------|------|
| 种子教师反馈 | 每 1-2 周 | "审题报告还要更细" |
| 外部需求（教导主任） | 即时响应 | 变种真题功能 |
| 技术发现（新框架/工具） | 即时评估 | LangGraph 1.2 发布 |
| 自测发现 bug | 即时修复 | KaTeX 渲染崩溃 |
