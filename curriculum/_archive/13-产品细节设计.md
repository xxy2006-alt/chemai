# 13 · 产品细节设计

## 产品细节不是 UI 好看，是每个交互决策都有用户反馈支撑

### 0. 设计系统的三次迭代

ChemAI 的视觉系统不是一次做对的。经历了三次迭代：

**v1（1 月）**：Academic Catalyst 设计系统 —— Oxford Blue `#002045` + 羊皮纸色 + glassmorphism AI 气泡
**v2（2 月 824c2c6）**：前端完全重做，"完美还原" Academic Catalyst，删 177+ 旧文件
**v3（3 月 8bba4e9）**：5 页面精简架构 —— 配色切换到暖羊皮纸 `#f7f4ed` + 刚果红 `#b43c28`

v2→v3 的切换原因：种子教师反馈"蓝色太冷、像银行系统，不像教育工具"。红色来自实验室试剂瓶标签的颜色联想，更符合化学主题。

### 0.1 设计系统的文档记录

每个版本的视觉变更都有文档记录：
- 1 月：`agent/REDESIGN.md`（竞品分析 + Academic Catalyst 设计系统）
- 2 月：commit `824c2c6` 的 commit message（"完美还原 Academic Catalyst"）
- 3 月：commit `8bba4e9`（"前端重设计 — 5页面精简架构 + Agent性能优化 + 视觉升级"）

### 1. 教师端配色与视觉系统

**设计源头**：教师端配色不是设计师定的——是从 `Academic Catalyst` 设计系统改造的，然后根据种子用户反馈调整。

```
主背景: #f7f4ed (暖羊皮纸)
主色: #b43c28 (刚果红，来自实验室试剂瓶标签的颜色联想)
文字: #1a1a1a (墨色)
辅色: #2c6e49 (甲基绿)
字体: Cormorant Garamond (衬线标题) + PingFang SC (中文正文)
```

**关键设计决策**：
- 不用纯白背景（#ffffff）——教师反馈"太白像考试卷，看久了累"
- 不用蓝色作为主色——"化学实验室里没有蓝色的试剂瓶"
- 侧边栏 240px——刚好放下 5 个导航项 + 用户信息

**代码位置**：`frontend/index.html` 的 `<style>` 块（行 6-150）定义了完整的 `.elem-nav`、`.sidebar`、`.msg-ai` 等组件样式。

### 2. 教师端导航结构的三次演进

**v1（8 项导航）**：AI助手 / 答题卡 / 考试工作台 / 题库 / 诊断 / 学生管理 / 学情面板 / 设置

种子用户反馈："太多了，常用的就前三个"→ 精简

**v2（5 项导航 + 图标）**：心理学 / 扫描 / 作业 / 健康 / 人群

种子用户反馈："图标不错，但考试工作台为什么不叫考试工作台"→ 恢复文字

**v3（当前：5 项紧凑图标 + Tooltip）**：`frontend/app.js:56-62` 的紧凑图标导航

每个图标 `34x34px`，hover 显示 Tooltip。移动端测试发现：教师用 iPad 访问时图标太小 → 加了 `min-width: 34px`。

### 3. 考试工作台的四个 Tab 设计

`frontend/pages/exam-v2.html` 是整个项目最复杂的单页面（917 行），包含 4 个 Tab：

1. **出题工作台**：AI 生成 + 手动录入 + 变种题
2. **题库管理**：已保存题库的浏览/编辑/删除
3. **历史真题库**：MinerU 导入的历年真题
4. **考试列表**：创建考试/添加题目/发布

**Tab 切换的实现**：不是 Vue Router，是 `sourceMode` 变量 + `v-show`。因为四个 Tab 的数据不需要懒加载——页面打开时一次性全加载。

**历史真题库的图片渲染**：`page_image` 路径从 JSON 读取，前端拼接完整 URL：
```html
<img :src="'/static/figures/' + encodeURIComponent(q.region||'') + '/' + q.year + '/' + q.page_image">
```

这个设计隐藏了一个坑：`page_image` 是相对路径 `figures/xxx.jpg`，前端需要知道 `region` 和 `year` 才能拼接。如果 JSON 里没有这两个字段，图片就加载不出来。修复方法是导入时在 JSON 里写完整路径。

### 4. 化学式渲染的坑

**问题**：MinerU 导入的 Markdown 包含 `$\mathrm{H_2SO_4}$` 这样的 LaTeX，前端渲染需要 KaTeX。

**v1**：不做 KaTeX，直接显示纯文本 → 化学式显示为 `$\mathrm{H_2SO_4}$` 原始字符串

**v2**：用 CDN 加载 KaTeX + marked，`renderChem()` 函数先过 marked 再过 KaTeX → 但 marked 的 `setOptions` 在 v12 被废弃，整段崩溃回退纯文本

**v3（最终方案）**：
```javascript
renderChem: function(t) {
  // 1. 保护 LaTeX 块（替换成占位符）
  h = h.replace(/\$\$([\s\S]*?)\$\$/g, ...)
  h = h.replace(/\$(?!\$)([\s\S]*?)\$/g, ...)
  // 2. Markdown → HTML
  h = marked.parse(h, {breaks: true, gfm: true})
  // 3. 恢复 LaTeX 块 → KaTeX 渲染
  blocks.forEach(function(b) {
    h = h.replace(b.key, katex.renderToString(b.tex, ...))
  })
}
```

关键教训：**marked 的 API 在 v12 变了**。`markdown-it` 或 `marked` 的版本升级是前端隐式依赖，没有 lockfile 时很容易踩坑。

### 5. 学生移动端的细节设计

设计原型 `frontend/m/design-v1.html` 的关键决策：

- **最大宽度 480px 居中**：iPhone 15 Pro 的 393px 逻辑宽度 + 边距
- **底部 Tab 栏**：4 个 Tab（AI助教/练习/错题/我的），Material Icons
- **不使用 Emoji**：教师端的设计评审中，Emoji 被认为"太像大众消费 App，不像教育工具"
- **不展示满分/排名**：学生端不显示排名，只显示正确率——来自教师反馈"学生直接看到排名会崩溃"
- **退出登录按钮放在"我的"页底部**：不在侧边栏、不在顶部栏——学生不容易误触

### 6. 内联面板 vs 页面跳转

ChemAI 的核心交互设计原则：**高频操作用内联面板，低频操作用页面跳转**。

| 操作 | 方式 | 理由 |
|------|------|------|
| 出题 | 内联面板 | 高频操作，在聊天中直接完成 |
| 诊断 | 内联面板 | 紧跟出题流程，不需要切换上下文 |
| 学生管理 | 页面跳转 | 低频操作，需要完整表格 |
| 学情面板 | 页面跳转 | 需要大屏图表 |
| 答题卡识别 | 页面跳转 | 需要文件上传 UI |

内联面板的技术实现：工具返回 `_component` 指令 → SSE adapter 发出 `component` 事件 → 前端 `agent.js` 的 `component` switch 分支渲染对应组件。

### 7. 错误处理的产品细节

**化学式渲染失败**：不显示红色错误信息，显示原始 LaTeX 文本（用户自己能看懂）

**网络错误**：显示"发送失败，请检查网络"——不显示具体 HTTP 状态码（用户不需要知道 500 vs 503）

**AI 超时**：30 秒无响应显示"AI 思考时间较长，请稍候..."——避免用户以为卡死了

**对话持久化失败**：静默处理——对话记录丢失是 bug，但不该打断用户当前的使用

## 8. 教师端的管理功能设计

### 8.1 考试管理

教师创建考试的流程（`frontend/pages/exam-v2.html` 行 867-900）：
1. 填写考试名称 + 选择班级 → `POST /api/exam/create`
2. 从真题库/题库中选择题目 → `POST /api/exam/{id}/questions`
3. 预览确认 → `GET /api/exam/{id}/questions`
4. 发布 → `POST /api/exam/{id}/publish`

关键设计：发布后不可修改题目（`question_stats.published = true` 时锁定）。这是种子教师的要求："万一学生已经看到了，我改了题目就乱套了"。

### 8.2 班级管理

`students` 表的设计（`app/models/database.py`）：
- `barrier_type` JSON 字段：动态更新，每次诊断后覆盖
- `exercises_completed`：累计练习数
- `last_exercise_at`：最近练习时间

教师端可以看到每个学生的障碍分布和练习进度。学生端看不到排名，只能看到自己的数据。

### 8.3 权限设计

4 个角色（`accounts.role`）的权限矩阵：

| 功能 | admin | 学科组长 | 教师 | 学生 |
|------|-------|---------|------|------|
| 出题/题库 | ✅ | ✅ | ✅ | ❌ |
| 考试管理 | ✅ | ✅ | ✅ | ❌ |
| 学生管理 | ✅ | ✅ | ❌ | ❌ |
| 障碍诊断 | ✅ | ✅ | ✅ | ❌ |
| AI 对话 | ✅ | ✅ | ✅ | ✅ |
| 练习/错题 | ❌ | ❌ | ❌ | ✅ |
| 学校管理 | ✅ | ❌ | ❌ | ❌ |

权限在前端侧边栏渲染时过滤（`app.js:45-62`），后端中间件验证（`app/main.py:57-78`）。

## 9. 学生端的无障碍设计

### 9.1 不显示排名

学生端只显示正确率和知识点分析，不显示班级排名。来自教师反馈："学生直接发会崩溃，要先过我这一关"。

### 9.2 错题本的"温柔"设计

错题本不叫"错题本"——在 UI 上叫"待复习"。变式题按钮不叫"重做"——叫"做一组相似的"。这些措辞来自教师的建议："别让学生觉得自己很差"。

### 9.3 移动端适配的细节

- 最大宽度 480px（适配 iPhone 15 Pro 的 393px + 边距）
- Tab 栏高度 50px（拇指舒适区）
- 输入框在键盘弹出时自动上移（`scrollIntoView`）
- 底部安全区适配（`env(safe-area-inset-bottom)`）
