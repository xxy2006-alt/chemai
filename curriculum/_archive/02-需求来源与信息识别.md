# CHEM AI 需求来源与信息识别

## 1. 需求来源全景图

ChemAI 项目的需求来自六个渠道，按可信度和优先级分层：

```
优先级降序：
一级来源（行为证据）  → 用户观察 + 使用数据
二级来源（表达需求）  → 深度访谈 + 问卷调研
三级来源（推导需求）  → JTBD 分析 + 竞品对标
四级来源（外部驱动）  → 学校行政要求 + 政策变化
五级来源（技术驱动）  → LLM 新能力 + 新开源工具
六级来源（假设驱动）  → 产品团队的直觉假设
```

### 1.1 一级来源：用户观察与使用数据

**三轮迭代式访谈**
- 第一轮（2026 年 4 月初）：基础角色扮演访谈，了解教师日常工作流程和核心痛点
- 第二轮（2026 年 4 月中）：深化访谈，聚焦错题统计和出题审题的具体场景
- 第三轮（2026 年 4 月末）：教练点评式访谈，验证前期假设，提炼 JTBD

**种子用户内测反馈**
- 邵阳县第一中学一位化学教师（教龄 18 年），作为种子用户持续提供反馈
- 反馈形式：线上访谈（每两周 30 分钟）+ 阶段性内测试用
- 关键反馈事件：
  - "化学方程式配平错误一次就放弃"——催生了 `chemical_balance` 审核工具
  - "AI 出题后还要我自己全做一遍验题那就没意义了"——催生了三维安全审核报告
  - "分数差不多的两个学生，可能一个属于第二类，一个属于第三类"——确定了三维障碍诊断模型

### 1.2 二级来源：定量调研数据

**需求调研问卷**
- 目标：验证定性访谈中的假设，获取量化优先级数据
- 方法：结构化问卷，覆盖功能需求/使用场景/付费意愿三个维度
- 样本量：目标高中化学教师群体
- 关键发现：
  - 错题统计功能需求强度最高（100% 受访者标记为"刚需"）
  - 付费意愿集中在月付 50-100 元 / 年付 600-1200 元
  - 信任红线：化学方程式系数错误 = 零容忍（100% 一致）
  - 推荐意愿：需要产品稳定运行 3 个月以上才会推荐给同事

### 1.3 三级来源：JTBD 系统分析

从三轮访谈中提炼的 JTBD（Jobs-To-Be-Done）框架，将需求分为三个维度：

**功能 Job（7 项）**
1. 快速获得班级错题分布统计（按知识点聚合）
2. 5 分钟内完成 AI 题目安全审核
3. 获得三维分析报告（知识点/陷阱/历年真题对比）
4. 生成面向不同接收者的定制化错题报告（学生版/家长版）
5. 为学生提供虚拟化学实验
6. 识别学生的真实障碍类型（概念/审题/表述）
7. 将自适应练习自动推送给学生

**社交 Job（2 项）**
8. 在同事群体中成为"善用工具"的专业形象
9. 通过推荐经过验证的工具维护自己的判断力和公信力

**情感 Job（3 项）**
10. 给予 90+ 人班级中每个学生一定程度的个性化关注
11. 不因工具质量问题在学生面前失去专业权威
12. 不因学习工具使用方法而感到时间被浪费

### 1.4 四级来源：学校行政与政策需求

- **公开课信息化要求**：教育部门要求教师公开课展示信息化教学手段
- **教材版本对齐**：湖南省使用人教版教材，功能需对齐教材编排和考纲
- **新高考 3+3 模式**：化学为选考科目，题型灵活，AI 需快速适应变化

用户原话："帮我完成行政上报的工具，我第一天就绕过去"——这个反馈推动了产品设计原则：**功能必须为教学服务，不为了"信息化"而信息化**。

### 1.5 五级来源：技术演进驱动

- LangGraph 1.2 发布 → 催生 Multi-Agent 架构重构
- MinerU v3.4 精度突破 → OCR 管线从 Baidu API 迁移到本地 pipeline
- DeepSeek 联网搜索 → web_search 工具可靠性提升
- AsyncSqliteSaver → 对话持久化方案落地

### 1.6 六级来源：产品假设

**教导主任变种真题需求（新需求注入）**
- 来源：邵阳县第一中学教导主任直接提出的需求
- 背景：教师在出卷时需要基于历年真题生成同考点、同难度、同题型的变种题
- 核心诉求：不改变真题的考查本质，只替换情境/数据/选项
- 需求边界：化学方程式系数不能变、反应条件不能变、产物不能变

**产品假设清单（15 条）**
| 优先级 | 假设 | 验证方法 | 状态 |
|--------|------|---------|------|
| P0 | AI 出题+三维审核报告能让教师在 5 分钟内验证一道题 | 计时可用性测试 | ✅ 已验证 |
| P0 | 化学方程式系数错误触发 100% 放弃 | 错误注入测试 | ✅ 已验证（访谈确认）|
| P1 | 障碍类型诊断准确率 ≥ 70% | 教师标注对比 | ⏳ 验证中 |
| P1 | 自适应练习比随机练习提分 ≥ 5% | A/B 测试 | ⏳ 未验证 |

## 2. 信息识别方法

### 2.1 信号 vs 噪音识别框架

```
信号（值得深挖）                   噪音（可以忽略）
─────────────────────────          ─────────────────
用户主动描述的具体场景              泛泛的"好用/不好用"
用户愿意花时间讨论的问题            "如果...可能..."的假设
用户表达了情绪（愤怒/焦虑/疲惫）    礼貌性附和
用户已经尝试过解决方案              第三方转述的"需求"
用户提出了具体的数据或量化指标      技术炫技型需求
重复出现≥3次的反馈                 一次性提到的话题
```

### 2.2 实际应用案例

**案例 1：从一句话需求到产品功能**

- 原始需求（噪音形式）："老师，能不能让 AI 出题的时候别出错？"
- 信号提炼后："老师每次使用 AI 出题后，需要花 30 分钟自己重新做一遍全部题目来验证正确性，这不是研发愿意接受的用户体验"
- 功能转化：`chemical_balance` 工具 + `audit_chemical_equation` 函数（行 `app/services/chemical_balance.py:1-150`），基于 valence 规则和反应条件数据库，对每道 AI 生成的题目做四维审核（系数/条件/产物/结构）
- 关键决策：审核结果不是简单的"通过/不通过"，而是生成结构化报告（`auditDims`），包含 warning 级别和 block 级别

**案例 2：隐含需求识别**

- 用户从未直接说"我需要一个 Agent 系统"
- 但从行为中提炼出隐含需求：
  - 用户在不同场景间频繁切换（搜题 → 出题 → 诊断 → 讲解）
  - 每个场景需要不同的交互模式（搜索要快、出题要稳、诊断要准、讲解要引导）
  - 用户不想学习 6 个独立工具的使用方法
- 推导方案：LangGraph Multi-Agent（`agent/langgraph_agent.py:426`），1 个协调器 + 6 个领域子专家，用户只需要一个聊天入口

**案例 3：教导主任变种真题需求识别**

- 原始表达（教师转述）："主任说能不能把历年真题改成不同版本让学生练"
- 信号分析：
  - 需求方是教导主任（非一线教师），需求类型属于行政推动
  - 核心场景是月考/期中考试命题——教师需要多套等价试卷防作弊
  - 技术本质是"保持考查目标不变，替换表层信息"
- 功能方案（`agent/tools.py` 中 `generate_questions` 的 `variant_source` 参数）：
  - 选一道真题作为蓝本 → 提取考点/难度/题型 → LLM 生成同构变体
  - 变体约束：题干情境可换、数据可换、选项顺序可换，但方程式/反应条件/产物不变

## 3. 需求优先级的动态调整

项目实施中优先级经历过三次重大调整：

| 时间 | 触发事件 | 调整内容 |
|------|---------|---------|
| Week 2 | Baidu OCR 识别率低 | OCR 管线从 API 迁移到 MinerU 本地 pipeline，P1 升级为 P0 |
| Week 4 | LangGraph 1.2 发布 | Agent 架构从单 Agent 重构为 Multi-Agent，工期增加 1 周 |
| Week 6 | 教导主任提出变种题需求 | 新增 `variant_source` 参数，插入当前迭代 |
