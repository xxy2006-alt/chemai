# 07 · 场景假设

## 场景假设不是凭空编的，是从访谈里拆出来的

ChemAI 项目启动时定义了 6 个核心场景，每个都来自用户的实际行为描述。场景假设的目的是：在写第一行代码之前，先确定"用户到底在什么情况下、做什么事、期待什么结果"。

### 场景 1：月考后错题统计

**用户原话**："每次月考完我要花一个半小时在那数哪道题多少人错。"

**拆解后的场景假设**：
- When：每次月考/期中/期末考试结束后 2 小时内
- Who：化学教师（独自一人，在办公室）
- What：打开 Excel，对着答题卡一张张统计——哪道题错了多少人、哪个知识点高频出错
- Pain：1.5 小时重复劳动、无人认可、占用了备课时间
- Expect：一个工具能自动完成这个统计，输出按知识点聚合的错题分布报告

**对应实现**：`app/api/exam.py:get_exam_results(exam_id)` + `student_answers` 表的 `is_correct`、`barrier_type` 字段

**数据验证**：用 1005 条初始答题记录跑统计，生成班级级别错题分布报告（按知识点聚合）。统计逻辑在 `app/api/exam.py:226-265`，返回 `question_results` 含每道题的正确/错误人数。

### 场景 2：AI 出题 + 安全审核

**用户原话**："用了 AI 出题还是要我自己全做一遍验题，那不如我自己出。"

**拆解后的场景假设**：
- When：准备月考/单元测试卷时（每 2-3 周一次）
- Who：化学教师
- What：用 AI 生成 10-15 道题目，但需要逐题验证正确性——化学方程式系数、反应条件、产物
- Pain：30 分钟验题时间、一次错误就触发对工具的全面放弃
- Expect：AI 出题 + 自动审核 = 5 分钟内完成验证决策

**对应实现**：`agent/tools.py:chemical_balance` + `app/services/chemical_balance.py` + `auditDims` 四维审核

### 场景 3：学生障碍类型诊断

**用户原话**："分数差不多的两个学生，可能一个属于第二类（审题障碍），一个属于第三类（表述障碍）。"

**拆解后的场景假设**：
- When：每次考试/练习后
- Who：化学教师
- What：不是简单看分数排名，而是识别每个学生的真实障碍类型——是知识点没懂？还是题目没读懂？还是懂了但写不对？
- Pain：90+ 人无法逐个分析，只能凭感觉分类
- Expect：自动诊断每个学生的障碍类型，输出三维分布

**对应实现**：`agent/tools.py:diagnose_barrier(student_id_or_class_id)` + `students` 表的 `barrier_type` JSON 字段

**验证数据**：第一次用 1005 条答题记录跑诊断，分类为 concept/reading/expression 三类的准确率约 60-70%，教师反馈"大致对但还需要样本积累"。

### 场景 4：学生自主练习

**用户原话**："班里十几二十个学生明显跟不上，不是他们不聪明。"

**拆解后的场景假设**：
- When：课后/周末自修时间
- Who：学生（手机端）
- What：看到教师布置的练习 → 逐题作答 → 查看结果和错题
- Pain：不知道自己的薄弱点在哪、做错题不知道为什么错
- Expect：个性化练习 + 错题本 + 变式题

**对应实现**：`frontend/m/practice.html` + `frontend/m/wrong.html` + `GET /api/practice/student/{id}/tasks`

**实际数据**：首次用 67 人学生数据测试，练习提交接口 `POST /api/practice/submit` 处理一条答案约 50ms（SQLite 插入）。

### 场景 5：基于错误原因的变种题生成

**用户原话（教导主任）**："能不能把历年真题改成不同版本让学生练？"

**拆解后的场景假设**：
- When：月考/期中考试命题阶段
- Who：教导主任推动，教师执行
- What：选一道真题作为蓝本 → 保持考点/难度/题型不变 → 替换题干情境、数据、选项
- Pain：同一次考试不同考场需要多套等价试卷防作弊；但人工出多套耗时巨大
- Expect：选蓝本 → 一键生成 3-5 个变种

**对应实现**（开发中）：`agent/tools.py:generate_questions(variant_source=qid)`

**技术约束**：变种题的四条红线——化学方程式系数不能变、反应条件不能变、产物不能变、考查知识点不能变

### 场景 6：教师通过 AI 对话获取教研信息

**用户原话**："请讲解氧化还原反应"→ 期望得到考点分布、学生常见误区、教学策略，不是被当成学生来教基础概念。

**拆解后的场景假设**：
- When：备课阶段
- Who：化学教师
- What：通过 AI 对话获取结构化教研信息
- Pain：通用 AI 把教师当成学生，反问"你先说说你的理解"
- Expect：直接给考点分析、命题趋势、教学策略

**对应实现**：`agent/tools.py:chemistry_tutor(persona="teacher")` + `agent/langgraph_agent.py:_current_persona`

**实际验证**：2026-06-27 通过日志确认，`persona=teacher` 时 `chemistry_tutor` 正确走教研分支。

### 场景 4（扩展）：学生练习的完整交互流程

学生端练习的完整交互有 5 个状态，每个状态都有对应的代码：

**状态 1：任务列表**（`practice.html` 的 `loadTasks()`）
- API：`GET /api/practice/student/{id}/tasks`
- 渲染：待完成卡片（标题+题数+难度+知识点标签）+ 已完成列表（折叠）
- 数据：来自 `app/api/practice.py`，从 `student_answers` 表 JOIN `exam_records`

**状态 2：开始练习**（`startPractice(pid)`）
- API：`GET /api/practice/student/{id}/practice/{pid}`
- 加载题目列表 → `state.quiz` 数组 → `renderQuiz()`

**状态 3：逐题作答**（`selectOpt(i)`）
- 每题有选项卡片（`.quiz-opt`），点击选中 → `state.answers[qIdx] = i` → 重新渲染
- 上一题/下一题按钮带禁用态（第 1 题禁用上一题，最后题显示提交）

**状态 4：提交**（`submitAnswers()`）
- API：`POST /api/practice/submit`
- 请求体：`{practice_id, student_id, answers: [{question_id, student_answer}]}`
- 响应：`{success, data: {correct_count, total_count}}`

**状态 5：结果展示**
- 显示正确率（大号分数 + 百分比）
- "返回练习列表"按钮

### 场景 5（扩展）：变种题的教师审核流程

变种题不是"生成完就用"——必须经过教师的审核：

1. AI 生成变种 → `generate_questions(variant_source=qid)` → 3 个变种 JSON
2. `chemical_balance` 自动审核 → 四维检查（系数/条件/产物/结构）
3. 教师人工审核 → 对比原题和变种 → 判断"等价"
4. 通过 → `save_to_bank` 保存到题库
5. 不通过 → 回到步骤 1，调整 Prompt 重生成

这个流程的核心约束：**教师必须在环内**。不能自动保存变种题，必须人工确认等价性。

### 场景 6（扩展）：教师对话的完整 Persona 流转

教师说"讲解氧化还原反应"的完整流转：

1. Gateway（`agent/gateway.py:276`）：匹配关键词"讲解" → `tools.append("chemistry_tutor")`
2. `_route_agent`：`chemistry_tutor` → `tutor_expert`（唯一匹配，low confidence）
3. Coordinator `_coordinator_node`（行 377）：`pre_routed_agent` 为空 → LLM 兜底
4. LLM 路由工具 `route_to_tutor_expert` → `router` → `target_agent = "tutor_expert"`
5. `tutor_expert` 子专家（行 269-273）：prompt 判断 `_current_persona == "teacher"`
6. 调用 `chemistry_tutor(persona="teacher")`（`agent/tools.py:309`）
7. 工具内部（行 322）：`if persona == "teacher":` → 教研模式 prompt

这个流转在 3 月 29 日之前只到第 6 步就卡住了——`persona` 传的是默认值 `"tutor"`。

### 场景假设的验证闭环

每个场景假设在代码实现后必须经过三次验证：
1. 开发者自测：代码跑通，数据正确
2. 种子用户反馈：教师实际试用，确认"这就是我要的"
3. 边界压力测试：异常输入、极端数据、错误注入
