# 12 · 提示词工程

## Prompt Engineering 不是玄学，是反复试出来的

ChemAI 项目的 prompt 不是一次写对的。每个 prompt 都经历了"写 → 测试 → 发现不稳定 → 加约束 → 再测试"的循环。以下是各组 prompt 的实际版本演进。

### 1. 协调器路由 Prompt（agent/gateway.py:25-58）

**v1（问题版）**：LLM 自己判断路由，10 次测试中 3 次路由错误

**v2（关键词版）**：不再依赖 LLM 判断，改用规则引擎
```python
_has_qword = any(kw in text for kw in ["题","题目","卷子","卷"])
_has_gen = any(kw in text for kw in ["出","生成","组","来几道","给几道"])
if _has_qword and _has_gen:
    tools.append("show_exam_workbench")
```
这是最关键的一次改进——从"让 LLM 猜"变成"规则匹配"。准确率从 70% 提到 100%。

**v3（当前版）**：规则引擎 + LLM 兜底。高置信度（2+ 工具指向同一专家）直接路由，低置信度（单工具匹配）LLM 兜底。
```python
if unique_agents == 1:
    intent.target_agent = list(agents.keys())[0]
    intent.confidence = "high" if max_count >= 2 else "low"
elif max_count >= 2 and max_count >= total_tools * 0.6:
    intent.target_agent = max(agents, key=agents.get)
```

关键教训：**LLM 不适合做确定性路由**。用规则做确定性判断，只在模糊场景才让 LLM 介入。

### 2. chemistry_tutor 的 Persona 切换（agent/tools.py:309-342）

**v1（学生版）**：
```
你是高中化学AI助教。学生水平: {student_level}。
1. 引导式教学: 不直接给答案，先问学生"你是怎么想的"
2. 分步讲解: 复杂问题拆成2-3步，每步确认理解
```

当教师用它时：被反问"你先说说你的理解"→ 教师炸了

**v2（Persona 分离）**：
```python
if persona == "teacher":
    system_prompt = """你是高中化学教研助手，正在协助一位化学教师备课和教研。
    1. 专业深度：提供高考考点分布、命题趋势、评分标准等教研级信息
    2. 教学策略：给出课堂讲解思路、实验演示建议、习题设计方向
    3. 学生误区：列举该知识点的常见错误认知和纠正方法
    4. 效率优先：直接给出结构化分析，不要反问教师基础问题
    """
else:
    system_prompt = f"""你是高中化学AI助教。学生水平: {student_level}。
    1. 引导式教学..."""
```

关键教训：**同一个工具，不同 Persona 必须有不同的 system prompt**。Persona 不是参数，是 prompt 分支。

### 3. Sub-Agent 必须调工具的约束（agent/langgraph_agent.py:247-251）

```python
_UNIFIED_PROMPT = (
    "你必须调用一个工具。阅读每个工具的描述来决定用哪个。"
    "不确定时，选择最可能相关的工具并调用它。"
    "禁止在不调用工具的情况下直接生成回复。"
)
```

这句话写了三遍强调"必须调用工具"——因为 DeepSeek 在 v1 版本中有约 20% 的概率不调工具直接生成回答。加了"禁止"后降到约 2%。

### 4. search_expert 的联网搜索 Prompt（agent/langgraph_agent.py:254-258）

```python
"涉及2025年及以后、最新、近期、今年、当前的内容，必须优先调 web_search。"
"search_exam_bank 无结果时，立刻改用 web_search。"
"禁止凭训练数据回答时效性问题。"
```

这三句话解决了"2026 年了还告诉用户 2026 年还没到"的问题。不是因为加了联网搜索能力（能力一直有）——是因为 Prompt 没告诉 LLM "应该用"。

### 5. MinerU 内容导入的 LLM Prompt（import_mineru_paper.py）

**v1（让 LLM 重写 content）**：
```
你是高中化学教研员。从以下MinerU解析的高考化学题目Markdown中，提取结构化信息。
```
→ 问题：LLM 重写 content 时会截断（max_tokens 不够）+ 混入分析

**v2（只用 LLM 提取元数据）**：
```
从以下高考化学题目Markdown中提取: 答案、简短解析、知识点、难度、题型。
```
→ content 直接用 MinerU 原始 Markdown，不做重写。content 长度从 2000 字提到 12000 字。

### Prompt 调试的通用方法

1. **先测 10 次**：每个 prompt 变更后，用相同的输入测 10 次，统计正确率
2. **看原始输出**：不只看最终结果，要看 SSE 事件的 `tool_call` 和 `tool_result`
3. **加约束而不是加解释**：`"禁止 X"` 比 `"请尽量 X"` 有效
4. **单独测试边界**：构造极端输入（空输入、超长输入、特殊字符）测 prompt 是否崩

### 6. 实际测试记录

**测试 1：Sub-Agent 是否调工具**

测试方法：给每个 sub-agent 发 10 条测试消息，统计调工具的比例。

| Sub-Agent | v1（无强制约束） | v2（"你必须调用一个工具"） | v3（加"禁止不调用"） |
|-----------|----------------|------------------------|-------------------|
| search_expert | 7/10 | 9/10 | 10/10 |
| exam_expert | 8/10 | 9/10 | 10/10 |
| diagnosis_expert | 6/10 | 8/10 | 9/10 |
| tutor_expert | 8/10 | 9/10 | 10/10 |

v3 的改进来自 `_SUB_AGENT_OUTPUT_CONTRACT`（`agent/langgraph_agent.py:165-170`）：
```
你必须先调用至少一个工具。
工具返回后，基于工具返回的 result 字段输出。
如果工具返回 error，将 error 文本原样输出。
如果工具返回了 _component，不要输出任何额外文字。
严禁跳过工具调用直接生成回复。
```

五句话，每句都针对一个具体问题：
1. "必须"→ 解决 LLM 不调工具
2. "基于 result"→ 解决 LLM 编造结果
3. "error 原样输出"→ 解决 LLM 美化错误信息
4. "_component 不输出额外文字"→ 解决 LLM 在内联面板前加废话
5. "严禁跳过"→ 双重强调

**测试 2：Gateway 关键词匹配 vs LLM 路由**

20 条测试消息，对比纯 LLM 路由 vs 关键词预路由：

| 方案 | 正确率 | 平均延迟 | 说明 |
|------|--------|---------|------|
| 纯 LLM（v1） | 14/20 (70%) | 3.2s | Coordinator LLM 判断 |
| 关键词预路由（v3） | 20/20 (100%) | 0.005s | Gateway 规则匹配 |

关键词预路由只需 5ms（字符串匹配），LLM 路由需要 3.2s（网络+推理）。100% 准确率 + 600x 速度提升。

**测试 3：联网搜索 Prompt 优化**

同一个问题"上网搜索 2026 年高考改革"，测试不同 system prompt：

| system prompt | 结果 | 问题 |
|--------------|------|------|
| （无 system prompt） | "截至 2024 年，2026 尚未到来" | MiMo 用训练数据覆盖搜索结果 |
| "当前日期是 2026 年" | 仍说"截至 2024 年" | MiMo 优先训练数据 |
| "用搜索结果回答，不要提训练数据" | 部分改善 | 仍有截断 |
| 最终方案：不用 MiMo | Bing HTTP 直搜 + DeepSeek 总结 | 彻底解决 |

最终放弃在 system prompt 层面修复——MiMo 的 `enable_search` 搜索确实执行了，但模型在回应中追加了训练数据截止声明。根本解决方案是换 Provider（Bing HTTP 直搜 + DeepSeek 总结）。

### 7. Prompt 变更的回归测试

每次修改 Agent 的 system prompt 后，必跑 `evals/test_langgraph_agent.py --all`：

```bash
# 1. 改 prompt
# 2. 跑全量测试
python evals/test_langgraph_agent.py --all
# 3. 如果 20/20 Golden 场景全部通过 → 提交
# 4. 如果有回归 → 回滚 prompt → 分析失败原因 → 重新调整
```

3 月的一次 Prompt 变更中，tutor_expert 的 prompt 从"禁止说开场白"改成"禁止说不必要的问候语"，结果 diagnosis_expert 的路由准确率从 100% 掉到 80%。根因：两个 expert 的 prompt 共享了 `_UNIFIED_PROMPT`，改动影响了 token 分布。修复：把共享 prompt 拆成独立 prompt，不做全局修改。
