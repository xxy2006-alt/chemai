# 17 · 测试调优与性能优化

## 性能调优不是事后做的——是边开发边测的

ChemAI 的性能瓶颈不在代码，在外部 API 和模型推理。每一层都有实测数据。

### 1. 端到端延迟拆解（3 月实测，DeepSeek API）

完整的"AI 对话"延迟拆解：

```
用户点击发送
  │ ~50ms  ─ 前端 fetch 请求构造 + DOM 更新
  │ ~15ms  ─ FastAPI 中间件（CORS + auth middleware）
  │ ~5ms   ─ Gateway classify() 关键词匹配 (agent/gateway.py:174-289)
  │ ~200ms ─ 网络往返到 DeepSeek API (api.deepseek.com)
  │ ~2-5s  ─ LLM 推理（首 token）
  │ ~50ms/token ─ 后续 token（SSE 流式，每 token 约 50ms）
  │ ~10ms  ─ 前端 renderChem() 渲染
  │ ~5ms   ─ AsyncSqliteSaver 写入 checkpoint
  └ 总计: 2.5-6s（取决于回复长度，通常 200-500 字）
```

瓶颈在 LLM 推理（占比 >85%），不在前端、不在网络、不在数据库。

### 2. MinerU Pipeline 耗时拆解

2020 年全国卷（22 页 PDF，纯 CPU 推理，3 月实测）：

| 阶段 | 模型 | 数据量 | 耗时 |
|------|------|--------|------|
| Layout 检测 | PP-DocLayoutV2 | 22 页 | 37s |
| MFR 公式识别 | UnimerNet-Small | 414 个公式 | 9m27s |
| 表格检测+OCR | SLANet+/UNet | 5 个表格 | ~30s |
| 文本 OCR | PaddleOCR | 214 块文本区 | ~5min |
| **总计** | | | **~15min** |

MFR 公式识别占了总耗时的 63%。因为每页平均 19 个公式，22 页共 414 个 LaTeX 表达式，每个都需要单独的模型推理。

GPU 推理预计降至 2-3 分钟。但 MVP 阶段未做——导入是一次性操作（一学期导一次），15 分钟可接受。

### 3. 已完成的 6 项优化

**优化 1：LLM 三路 fallback（`app/services/llm_service.py:82-95`）**

不是优化速度，是优化可用性。DeepSeek 在 1 月 15-16 日有 12 小时故障，三路 fallback 保证零服务中断。

```python
order = [
    ("mimo", self.mimo_key, self.MIMO_URL, self.MIMO_MODEL),
    ("dashscope", self.dashscope_key, self.DASHSCOPE_URL, self.model),
    ("deepseek", self.deepseek_key, self.DEEPSEEK_URL, "deepseek-chat"),
]
```

**优化 2：SSE 心跳帧（`agent/channel/langgraph_channel.py`）**

每 15 秒发一个 `data: [PING]\n\n` 帧。防止企业代理/nginx 超时断开 SSE 连接。特别重要——目标学校的企业网络配置了 30 秒 HTTP 超时。

**优化 3：前端缓存策略**

`agent.js?v=21` 版本号递增策略：每次 JS 改动后递增版本号，强制浏览器重新加载新版本。CDN 脚本（KaTeX/marked/Vue/Tailwind）设 1 年缓存。

**优化 4：SQLite WAL 模式**

`chemai.db` 使用 WAL（Write-Ahead Logging）模式。实际并发 <5 个请求同时读写，WAL 足够。不需要连接池。

**优化 5：MinerU 模型本地缓存**

7 个 pipeline 模型（4-5GB）下载一次后永久缓存在 `C:\Users\Administrator\.cache\huggingface\hub\models--opendatalab--PDF-Extract-Kit-1.0\`。后续导入不需要重新下载。

**优化 6：AsyncSqliteSaver 懒加载**

```python
_checkpointer = None
async def _get_checkpointer():
    global _checkpointer
    if _checkpointer is None:
        conn = await aiosqlite.connect("chemai_checkpoints.db")
        _checkpointer = AsyncSqliteSaver(conn)
    return _checkpointer
```

不是每次请求都创建新连接。首个请求初始化后缓存，后续复用。

### 4. 参数调优记录

| 参数 | 初始值 | 调优后 | 原因 |
|------|--------|--------|------|
| LLM max_tokens | 2000 | 4000-5000 | 化学式 LaTeX 占用大量 token，2000 不够 |
| LLM temperature | 0.7 | 0.1-0.3 | 化学领域需要确定性，创造性会导致配平错误 |
| Agent recursion_limit | 10 | 7-8 | 过多递归导致超时，7 次够用 |
| MinerU page parallel | 1 | 1 | Windows multiprocessing spawn 模式不稳定 |
| SSE ping interval | 30s | 15s | 学校网络代理超时 30s，15s 心跳可保活 |
| web_search max_tokens | 500 | 2048-4096 | 联网搜索结果通常长，500 会截断 |

### 5. 不做的优化（刻意不做）

| 不做的事 | 原因 | 做的时间 |
|---------|------|---------|
| 数据库索引 | 4.5MB SQLite，全表扫描 <10ms | 用户量 >1000 或 DB >100MB 时 |
| 前端打包/Bundle | 1300 行 JS，无框架 | 前端 >5000 行时 |
| API Rate Limiting | <5 个并发用户 | 用户量 >50 时 |
| Redis 缓存 | 无状态 API，无热点数据 | 引入排行榜/实时统计时 |
| CDN Edge Cache | 内网访问，外网 CDN 无意义 | 部署到公网时 |
| GPU 推理 | MinerU 导入是一次性操作 | 批量导入 >10 份试卷时 |

### 8. 当前性能瓶颈排序

| 排名 | 瓶颈 | 影响 | 缓解方案 |
|------|------|------|---------|
| 1 | MinerU 15min 导入 | 教师需等待，一学期一次 | GPU 推理（P2） |
