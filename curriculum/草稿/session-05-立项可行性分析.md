## 项目背景（给学生的概述）

前四节课你理解了用户、分析了竞品、排了功能优先级。现在你要面对一个更根本的问题：**这个产品值不值得做？**

"值不值得做"不是一个感觉问题，是一个计算问题。ChemAI 不是内部工具——它最终要面向付费用户。如果你算出来 TAM 只有 50 万、开发成本要 30 万、回本周期 3 年，那你可能不该做。如果你算出来存在一个风险的概率是 80%、一旦发生产品直接死亡，那你必须先解决这个风险再开始写代码。

ChemAI 在 Day 1 没有做这个分析——这是事后反思时补的。但你现在学的是一套完整的"数据护照"方法论，可行性分析必须放在写代码之前。

这节课你要完成四件事：PESTEL 宏观扫描（政策/经济/社会/技术/环境/法律）、TAM-SAM-SOM 市场估算（全国多大→我们能吃多大→我们先吃多大）、ROI 计算（花多少钱→赚多少钱→多久回本）、风险矩阵（什么可能出错→出错概率多大→影响多大→怎么防）。

### 步骤 2：TAM/SAM/SOM 市场规模估算

## 定义

- **TAM（Total Addressable Market）**：全国所有可能使用 ChemAI 的高中化学教师总数 × 年付费金额
- **SAM（Serviceable Addressable Market）**：TAM 中 ChemAI 当前产品形态能服务的部分
- **SOM（Serviceable Obtainable Market）**：SAM 中 ChemAI 在 1-2 年内实际能获取的部分

## 计算步骤

### Step 1：估算全国高中化学教师数量

逻辑链：
- 全国高中数量（参考公开数据）→ 每校平均化学教师数 → 总化学教师数
- 注意：只有带班教师（非行政岗）才会用这个产品
- 从总人数中排除：已退休、纯行政、不教课的教研组长

### Step 2：估算付费意愿和金额

基于 Session 3 访谈数据：
- 种子教师付费意愿：月付 50-100 元 / 年付 600-1200 元
- 考虑不同经济水平地区的付费差异
- 一线城市 vs 三四线城市的价格敏感度

### Step 3：TAM 计算

```
TAM = 全国高中化学教师数 × 年付费意愿比例 × 年均付费金额
```

给出低/中/高三种估算并说明假设。

### Step 4：SAM 计算

从 TAM 中扣除 ChemAI 当前无法服务的部分：
- 无稳定网络的偏远地区学校
- 不使用智能手机/电脑的教师（比例很低但存在）
- 完全拒绝 AI 工具的教师群体

```
SAM = TAM × 可达比例
```

### Step 5：SOM 计算

从 SAM 中估算 1-2 年内能获取的部分：
- 基于种子教师所在学校的同城扩散速度
- 基于口碑传播周期（访谈数据：推荐需要产品稳定运行 3 个月以上）
- 参考同类教育 SaaS 产品的早期增长曲线

```
SOM = SAM × 1-2年市占率
```

## 风险识别

从 5 个维度识别风险：

### 1. 技术风险
- LLM 化学推理能力不稳定
- OCR 识别精度不达标
- 系统性能和扩展性

### 2. 市场风险
- 竞品快速跟进（大厂抄袭门槛低）
- 用户付费意愿低于预期
- 目标市场增长不及预期

### 3. 用户风险
- 教师 AI 信任建立失败（"一次错误就放弃"）

- API 服务中断（DeepSeek 宕机）
- 月度 API 费用超预算
- 数据安全和隐私事件

### 5. 合规风险
- 教育数据合规要求变化
- AI 生成内容监管政策
- 学生隐私保护法规

## 评估标准

对每个风险评定：
- **概率**（1-5）：1=几乎不可能，5=几乎必然发生
- **影响**（1-5）：1=可忽略，5=产品死亡
- **风险等级** = 概率 × 影响
  - 🔴 高风险（≥15）：必须制定详细缓解计划
  - 🟡 中风险（8-14）：需要监控和预案
  - 🟢 低风险（<8）：接受或简单监控

## 发生了什么（教师参考）

### 1. 可行性分析为什么放在写代码之前？

ChemAI 项目实际开发中没有先做可行性分析——它是从"有个 idea"直接跳到"写代码"的。这是因为 ChemAI 最初是一个学习项目而非商业产品。但现在教学生的是一套完整的产品方法论，可行性分析必须放在实现之前。

PESTEL 的价值不在于预测未来（没人能预测），在于**系统性地扫描你可能忽略的风险和机会**。比如"AI 生成内容的法律责任"——如果你在开发前没想过这个问题，等产品上线后被投诉时才想，就太晚了。

### 2. TAM/SAM/SOM 的现实扭曲

学生在做 TAM 时容易犯三个错误：
- **TAM 过大**："全国有 X 万教师，所以市场是 X × 年费 = 几亿"——这是投资人讨厌的"中国市场很大所以我能成功"逻辑。TAM 要扣除非目标用户（不教课、不接受 AI、无付费能力）。
- **SAM 和 SOM 混淆**：SAM 是"你能服务的"，SOM 是"你能拿到的"。你能服务 1000 个不代表你能拿到 1000 个。
- **用百分比而不是具体路径估算 SOM**："我们拿 1% 就够了"——1% 怎么拿到？通过什么渠道？需要多长时间？这些问题比百分比本身重要。

### 3. ROI 的核心不是数字

ChemAI 真实情况：API 费用 <500 元/月，单人开发 12 周。所以第一年成本很低，回本容易。但这不是重点——重点是**用户获取成本**。如果你花 100 元获取一个年付 600 元的用户，你的 CAC（客户获取成本）是 100 元，LTV（用户生命周期价值）是 600 × 年数。只要 LTV/CAC > 3，商业模式成立。

学生做 ROI 时最重要的是**把假设写清楚**，而不是追求数字精确。3 个月后回头看，你的假设哪些对了、哪些错了、为什么——这比初始数字本身有价值 100 倍。

### 4. 风险矩阵的真正用途

风险矩阵不是为了"看起来专业"，是为了**决定你现在该做什么**。

ChemAI 的风险矩阵揭示了一个关键发现：技术风险（LLM 不稳定、OCR 精度）都排在中低优先级，而用户风险（信任崩塌）排在最高优先级。这意味着：你的最大风险不是你做不出来，是你做出来了没人敢用。

这个发现直接影响了开发策略：在写任何功能代码之前，先实现 chemical_balance 审核工具——因为它是对最高风险的直接缓解。

### 5. 经常出现的问题

**Q：学生做 TAM 估算时说"中国有 X 万教师，所以 TAM = X × 年费"**
A：这个逻辑漏掉了两个关键问题：（1）X 万教师中有多少人教化学？（2）多少人愿意付费？TAM 不是"所有人 × 定价"，是"目标用户 × 付费意愿比例 × 定价"。每一步缩小都有依据。

**Q：风险矩阵全是高风险 🔴**
A：如果所有风险都是高风险，等于没有优先级。风险矩阵的价值在于**区分哪些必须现在处理、哪些可以以后处理**。概率和影响的评分标准要统一——不能因为"感觉可怕"就把概率也打 5 分。
