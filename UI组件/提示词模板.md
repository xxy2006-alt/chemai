# UI 组件 · Vibe Coding 提示词模板

> 让 AI 写界面之前,先走 5 步:**问框架 → 选组件库 → 对组件名 → 写代码 → 要迭代**。
> 核心原则:组件库里有现成的,别让 AI 从零造轮子。

---

## 场景一 · 自己做项目(技术栈自己选)

自己从零做一个东西,框架和组件库都由你来定。

**完整对话示例:**

> **你:** 我要用 React 19 做一个个人作品集网站,组件库我选 Ant Design,可以吗?
> **AI:** 可以,React 配 antd 很常见。你想做什么效果?
>
> **你:** 做一个项目展示页:顶部导航栏,下面三张卡片并排,每张卡片有项目名、简介和「查看详情」按钮;点详情弹出一个 Modal,里面放项目截图和链接。
> **AI:** 好的,用 antd 的 Menu、Card、Modal 组件来实现。
>
> **你:** 卡片之间留点间距;Modal 打开时加个淡入动画;标题用大一点的字。
> **AI:** 已改好:卡片间距 24px,Modal 加了淡入,标题字号放大了。

**套路拆解:**
1. 先说自己的技术栈(React 19)——这是你自己的决定,不是 AI 猜的
2. 再说组件库(我选 Ant Design)
3. 再说要什么效果(导航栏、卡片、详情弹窗)
4. 迭代就是一句话:「间距大点」「加个动画」

---

## 场景二 · 公司项目(技术栈团队定好了)

进公司项目,框架和组件库不是你能选的,是团队定的。不用问 AI 选什么,直接告诉它项目现状。

**完整对话示例:**

> **你:** 我们公司项目是 Vue 3 + Element Plus,PC 管理后台。现在要给订单管理页加一个批量删除:勾选订单,点删除,弹确认框,确认后调接口,删完刷新列表。
> **AI:** 用 Element Plus 的 Table(多选)和 MessageBox.confirm 来实现。
>
> **你:** 确认框文案按我们公司规范写:标题「删除订单」,正文提示删了几条;删除失败的接口报错要弹错误提示。
> **AI:** 已按规范写好,失败时用 ElMessage.error 提示。
>
> **你:** 删除中的按钮加 loading,防止重复提交。
> **AI:** 已加。

**套路拆解:**
1. 开场直接报项目现状:框架(Vue 3)+ 组件库(Element Plus)+ 页面场景(PC 管理后台)
2. 组件名不确定就反问:「批量删除确认,Element Plus 里用哪个组件?」让 AI 报名字
3. 项目规范(文案、提示方式)是公司定的,直接说给 AI 听
4. 按钮 loading 这种细节,靠迭代一句句加

---

## 两个场景的区别

| | 自己做项目 | 公司项目 |
|---|---|---|
| 技术栈 | 自己选,先想好 React/Vue | 团队定的,报出来就行 |
| 组件库 | 自己挑(React→antd,Vue→Element Plus) | 团队用的,直接沿用 |
| 页面规范 | 自己说了算 | 公司规范优先,说给 AI 听 |
| 共同点 | 都用库里现成组件,都对组件名,都靠迭代打磨 |

## 常见框架 → 组件库对照

| 框架 | 常用组件库 | 场景 |
|---|---|---|
| React | Ant Design / MUI / Arco Design | PC 后台、中后台系统 |
| Vue | Element Plus / Naive UI / Ant Design Vue | PC 后台、中后台系统 |
| 移动端 H5 | Vant / Ant Design Mobile | 手机网页 |
| 小程序 | TDesign / Vant Weapp | 微信小程序 |
| 原生 HTML | 无(或 Web Components 库) | 简单页面 |
